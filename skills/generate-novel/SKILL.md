name: generate-novel
description: 按作者意图创作或补完整本小说，包括大纲、主体、伏笔、章节目录和逐章正文；不用于只讨论或只写一章。
---

## 交付目标

把完整故事写进当前作品。遵从作者的题材、视角、文风和目标章数；「约十章」可以直接定为十章。已有可用的大纲、素材、目录和正文是作者的事实，不删改既有稿件来重新开始。只有空目录、梗概、计划或聊天文字不算完成。

## 按现稿决定下一步

- 先调用不带参数的 `book_get_context` 看作品，不用再调用通用文件工具。规划大纲和有序目录，沿用已有章节 ID，为缺少的章节选短且稳定的新 ID。**在首次写入之前**，用 `book_get_context` 的 `novelGoal: { action: "register", chapterIds: [...] }` 登记按顺序排列的完整目标；不要只登记眼下要写的一章。若作者要接续本会话的任务，用 `novelGoal: { action: "resume" }` 获取原来的目标和创作方向，不重建目录；当前作者明确给了新的创作方向时，可在 resume 中传 `updateDirection: true`，新要求优先。
- 缺少资料时，用 `book_apply_changes` 提交大纲、主体和目录。大纲先给全书脉络及每章一句关键情节，约 1000 汉字；主体只列有情节用途的必要人物、物品、场景，每条一两句，十章通常 8–12 项即可。操作尽量合批但保持参数简短，资料较多则分成小批，禁止一次写长篇设定；先读到 `nextOffset` 为 `null`，需要长文档则按 ID 分页。本轮已提交且未变化的内容不需要重复取回。工具报告有未读或已变化的资料时，调用无参数 `book_get_context` 按 `nextOffset` 读完各页，或具体按 ID 补读；只读 `index` 不满足写入前提。采用大纲情节点时，用独立 Markdown 注释 `<!-- beat:stable-id -->`；只使用真实已有标记来关联。
- 用 `book_get_context` 的 `index: "chapters"`、`"subjects"` 或 `"beats"` 查校验器识别的稳定 ID。新增伏笔前先让所需的主体和章节实际存在，首批只写对剧情必要的伏笔，每条简述线索和回收，直接用真实 `setupChapterId` / `payoffChapterId` 和 `subjectIds`，不造 `setupBeatId` / `payoffBeatId` 占位。保留有效旧稿关系。遇到无效引用先查真实 ID，再修正未提交项；不能确认时报告具体缺项，不删必需关联、不盲目重放、不要先写受影响的正文。
- 用 `book_generate_chapter` 的 `draft` 逐章完整写出正文，等当前章保存成功再开始下一章。参数 `direction` 给本章的情节、长度和伏笔安排，既要承接前文，又不要提前揭示后续情节。作者未指定篇幅时，每章用约 1200–1800 汉字完成完整情节，不自行要求长章或一次输出整本。已有非空章直接沿用。工具报告断流、输出触限或版本冲突时，不重复调用相同失败请求、不跳过这章写后面；向作者说明已保存哪些章及怎么继续。
- 用 `book_get_context` 的 `novelGoal: { action: "check" }` 核对落盘结果。目标章的顺序和范围不能为报完成而缩减。只有确认所需资料、有效伏笔和所有目标章正文已保存才报告全书完成，否则明确说明未完成项。

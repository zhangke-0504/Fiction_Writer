## 交付目标

本轮要求交付整部故事（例如「根据设定生成10章内容」且未限定只写指定章节或仅追加几章），或明确续接原整书时，使用本流程；不要求出现「整书」或「完整小说」等词。只写指定章节、增补场景或续办局部待办时走对应局部工具，不登记或恢复整书；读到本指南不改变任务范围。

把完整故事写进当前作品。遵从作者的题材、视角、文风和目标章数；「约十章」可以直接定为十章。已有可用的大纲、说明、目录和正文是作者的现稿，不删改以重新开始。只有名称或空占位的资料不算说明，空目录、梗概和聊天也不算交付。

## 按现稿决定下一步

- 用 `book_get_context` 查看当前作品，不用通用文件工具。沿用已有章节 ID，为缺少的章选短且稳定的 ID。首次写入前，用 `book_task_scope` 登记 `novel.register`（作品 ID、完整章数 `count` 和简短 `purpose`），再通过 `book_get_context` 的 `novelGoal: { action: "register", chapterIds: [...] }` 激活完整有序目标（含已有稿章节），不按章反复登记；已确定必须交付的主体／伏笔可通过 `assetRefs: [{ type, id }]` 登记，后来发现的新项可按同一章范围增补。本轮明确续接同书同会话已保存的未完成整书目标时，先登记 `novel.resume`，再用 `novelGoal: { action: "resume" }` 核对现稿进度和原要求；仅当作者明确改变创作方向才设 `updateDirection: true`。若此前从未登记而作者明确续写，核对原要求、完整章数和现稿，走 `novel.register`，优先用 `sourceQuote` 引用原作者要求以保留方向。本轮整书范围已登记但收到 `novel_goal_required` 时照反馈激活，不改用普通单章绕过。
- 用 `book_apply_changes` 为缺项提交大纲和目录，大纲写全书脉络和每章关键情节，尽量按 `<!-- chapter:稳定章节ID -->` 或绑定到章的 `<!-- beat:稳定情节点ID -->` 分段。保持工具参数简短；修改已有资料先读全所需各页，`index` 只用来查校验器认可的 ID。
- 主体和伏笔需要说明时调用 `book_generate_assets`：按类别分小批（通常 2–4 项；长设定再少一点），`create` 传新 ID 和字段，`fill` 仅补空白／占位；不要用 `book_apply_changes` 建空卡或填说明。主体只写对本书有用的人物、物品、场景，说明稳定设定和有依据的状态，不堆长篇背景。伏笔只写剧情要用的线索，分清可见线索和回收真相；已确定的埋设／回收使用真实 `setupChapterId`、`payoffChapterId`，尚未确定可先省略字段，之后按目标补绑定，不另建卡或占位章。各目标分别按已有材料取材，不把空关联说明变成开工前提。保留已有非空说明与有效关联。提交成功且未被更改的资料不必再全量读取。引用错误就查目标索引；资产触限只缩小未提交的批次，不重放相同批次。
- 对每个当前空白目标章，用 `book_generate_chapter` 的 `draft`，从现稿指定本章任务、参与的 `subjectIds` 和需埋设／推进／回收的 `clueIds`；`direction` 只给简明的情节安排，不复述稿件、不提前写后章真相。没有作者篇幅要求时约 1200–1800 汉字。遇到已有后接正文时先读该章开场，只把需保持的条件与短原文位置放在 `nextBoundary`。已有非空章直接复用。只在真正必要的证据缺失时报告缺项，不先扫读或生成可选材料；整书资料要求仍在结算核对。若阻塞，按 `issues` 的真实类别与版本定向处理：仅空说明用 fill，已有说明查适用原文或调整合法安排，锚点错误查具体章／索引。条件没变化时不反复重放、不扫整书、不绕开写章工具；断流、触限或版本冲突终止时保留进度、不跳章。
- 如发现本轮从空白新写的章与已保存前章存在明确事实矛盾，可定向读取这两章，用 `book_patch_chapter` 提交目标章当前版本、少量精确旧句和新句，以及前章精确证据和版本。只纠正有据矛盾，不补写未确定的情节；不修改复用旧稿、续跑旧稿或已被作者更新的版本，不加固定审校阶段。按实际回执分别汇报已保存、已勘误和待确定的问题。
- 用 `novelGoal: { action: "check" }` 核对实际落盘。即使全部章有正文，也要补齐已列入目标的说明和关联；不要缩减所需产物来报完成。只对当前有缺口的操作调用相应工具，不要求已经齐全的资料重新生成。

---
name: story-consistency
description: 维护主体、伏笔、全书大纲之间的显式与剧情关联。
---

- 作品文件是事实来源。用 `book_get_context` 读取大纲、现有人物/物品/场景和伏笔；先用目录或 `book_search_text` 定位真实 ID，再按当前修订定向回读实际所需原文，不依赖旧聊天；没有变更不重复扫全书。
- 修改主体或伏笔时检查它在大纲中的安排，并检查关联主体、伏笔和章节。改大纲时反向检查受影响的主体和伏笔。需要完整资料时显式传 `includeBodies: true` 读取资料页；未包含全文的文档按 ID 和返回的 `nextOffset`／`revision` 继续读取。
- 不要全书重写。区分明确引用与自由文本中的剧情事实。沿用稳定 ID；新关联采用 `[显示名称](subjects/id.md)`、`foreshadowing/id.md`、`chapters/id.md`，章节/伏笔的结构化关系使用现有 ID。
- AI 新建、补齐或更新主体／伏笔说明用 `book_generate_assets`，明确目标 ID 与动作，不从工具安排推断对现稿的授权。已有说明默认保留；若只是补指定说明，不触碰章节正文字节。
- 作者要求在已写的故事中新增登场或情节时，不启动整书生成。按现有章节顺序选合适位置；新增主体用 `relatedSubjectIds` 关联实际已有的不同主体；新伏笔把埋设锚到要真正写入的章，回收位置是计划而非已经发生。可用 `book_get_context` 的 `index: "chapters"` 获取中期候选和可核验锚点。回收章仅计划，也须传真实 `payoffChapterId`，不用重写该章。伏笔提交结果的 `entryReady` 已给同章锚点、版本及关联 ID，可直接择一使用，不必重新查全文。新反派与本章要埋的伏笔须先已有提交结果，`insert` 参数指向它们的真实 ID，不能写完正文才补两张资料卡。只在作者只要求一处登场时选一章。若要求中期迹象、后期才露面，分别在中期留下迹象、在后期实际登场，每章单独提交，不能把登场移到中期。作者说直接改则直接执行，不把「想好怎么改」当作需要确认。读取目标章取得 `revision` 和唯一短原文，调用 `book_generate_chapter` 的 `insert`（`insertion: { revision, quote, place, outline }`）。通过 `outline: { revision, addition }` 只给该章大纲增补短说明，用 Markdown 写真实主体／伏笔链接；结合前后文输出新增登场／埋设片段，不创建另一章或覆盖原章。`revision` 均取当前读取结果；若已有明确冲突才需另选合法锚点，旧章尾短边界不足时提供 `nextBoundary`。
- 插入后发现本轮新增片段仍复述邻段，且尚有有效的 `insertionRef` 和该次提交 revision 时，用 `book_clean_insert_echo`；它只删除后端证明属于新增块的回声，不能改原稿或替换正文。清理被拒就如实报告，不用通用补丁或重写绕过。若回执返回 `pendingSync`，只重核仍获授权的受影响资料，分别汇报插入、清理和同步。
- 用 `book_apply_changes` 提交确定必要的元数据和关系修改，`fields` 只写变化字段。涉及已存正文的定点修改须有本轮作者明确授权：定向读取目标章和依据，使用 `book_patch_chapter`，不要调用 `book_apply_changes` 填正文，也不要用 `replace` 重写整章。新增场景仍走 `insert`；若需要后接约束，用 `nextBoundary` 提供证据，不自动修改邻章。删除仅限真正不再需要的资产，不因同名或剧情位置变化批量删除。
- 工具要求重新读取或报告部分写入时，先以磁盘实况为准，不重放原写入。向作者说明实际更新的资产和未确定的剧情问题，不能只说「已同步」。

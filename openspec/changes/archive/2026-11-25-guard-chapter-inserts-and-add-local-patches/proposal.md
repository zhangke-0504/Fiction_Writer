## Why

人工回归发现，局部插入可能在一次成功写入中带入重复句段或工作说明；整书生成后，Agent 即使发现可定位的前后文矛盾，也没有只修改目标句段的正文工具。实施后的绿灯侠复测进一步确认，重生成后的候选仍可能复述相邻旧段的开头，而普通正文补丁会拒绝仅获增补授权的任务；必须补查这种回声，并允许在不触碰旧正文的前提下清理本轮新插入片段。

## What Changes

- 对已保存章节的 `insert` 候选在提交前校验：剥离可确定的整段边界回声，识别句段重复、跨标点的边界前后缀重叠及明确的串稿信号。有问题时最多定向重生成一次，仍不合格则本处正文和随附大纲都不写；保留其他已提交内容。
- 为绑定小说的 Harness 增加 `book_patch_chapter`：从当前版本的正文定位精确、唯一的旧文，一次只提交一章的少量局部修订，保留范围外的正文、元数据、其他章节和资料。
- 允许当前作者明确要求的定点修订；整书 Run 另可在明确事实证据支持下，对本 Run 从空白生成且仍是本 Run 提交版本的章节作小范围自修。不得凭生成授权修改原有稿件、续跑复用稿或增写未经确定的剧情。
- 为增补 Run 增加受插入回执约束的边界回声清理：只删除本 Run 已保存的新片段内经核实的重复，不授权改旧正文、整章、其他位置或作品资料；受影响的同步必须重新核验。
- 按真实提交结果报告哪些地方改了、哪些仍缺证据或授权。保留整章重写的现有授权门槛和通用资料工具的正文限制；不引入新的编辑模式、全书去重或强制审校阶段。

## Capabilities

### New Capabilities

无新增独立 capability；变更纳入现有小说写作和诊断能力。

### Modified Capabilities

- `novel-writing-workflows`: 增加局部插入候选验收、受控的正文定点修订、同 Run 整书勘误与同 Run 插入回声清理，保持既有写作与保护边界。
- `local-diagnostic-logging`: 区分候选质量拒绝、定点修订／插入回声清理的拒绝及实际提交，只保留经白名单允许的元数据。

## Impact

- 后台写章、小说工具注册、定向读取、作者范围判定、版本保护、回执与诊断；同步更新写作及一致性 Skill 对工具的引导。
- 新工具复用现有 Markdown 提交和变更通知，不改变作品格式、用户界面或供应商 API；如需留存清理回执，兼容既有回执及会话记录，不迁移旧数据。
- 回归测试以磁盘内容、版本和实际回执为准，覆盖候选内部或邻段重复、短句加跨标点的部分复述、仅清理本 Run 的新增片段和同步引用复核，以及整书结束前只修正目标章的伤因矛盾。

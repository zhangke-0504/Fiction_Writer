## Goals / Non-Goals

**Goals:**

- 在 `insert` 提交前处理可确定的回声，拒绝仍含重复或明确稿外说明的候选；至多更正生成一次，并保留原稿和既有提交边界。
- 用单章、精确旧文和乐观版本控制提交局部修订。保留当前作者命令和同 Run 整书新稿事实勘误两条普通补丁授权路径。
- 为同 Run 已提交插入片段提供仅删除可证实回声的后备路径，旧正文不动，已同步证据不冒用旧版本。
- 让主 Agent 能定向定位问题、得到真实的提交回执并说明剩余问题，不必要求整章重写。

**Non-Goals:**

- 不做全章模糊去重、通用纠错或全书强制审校；不清洗旧稿，不把有意重复或小说世界内部引用的章节编号当成通用错误。
- 不放宽 `replace`、通用正文补丁、资料写入、通用文件工具、跨章方案或续接的授权；清理动作不改大纲、角色卡或伏笔，必要的资料同步仍走原有授权和工具。
- 不新增 UI 模式、额外会话或多 Agent 流程；不改变作品格式，不迁移现有稿件、日志或会话。

## Decisions

### 1. 插入验收在完整候选和提交之间

保留 `chapter-insertion.ts` 的修订及唯一原文锚点校验、短窗口取材与 `insertPassage` 的原文切片拼接。`writing-request.ts` 明说邻段是衔接参考，避免复述、章索引式剧情回指及工作说明。提示词是第一道提醒，不是落盘保证。

`draft.ts` 在协议完整、未取消、不过输出上限后，先走原有完整邻段回声剥离，再以有限的紧邻正文窗口和候选为范围检测：复制邻段中足够长的独立句／连续句段（含复制在候选内部），候选内相邻重复的完整句段，和明确外泄的工作说明或写章回指。只对安全的整段边界回声做自动剥离；其他命中不擅自删文本。CRLF、句界标点或轻微空白归一化只用于检测，不改保存文本；短应答、常见短语和小说内部引用章号不单独触发。不采用全章相似度或对名称、星期和错别字进行无上下文替换。

在现有整句规则旁加独立的「候选首／尾 ↔ 锚点两侧直接相邻正文段落」检测。比较连续的归一化前后缀，并保留归一化字符到原文范围的映射。允许短完整句与相邻的部分句合并计入同一边界证据，不要求双方有相同标点或句界。要判为高置信度明确回声，须有足够长且完全相同的连续文字（初始沿用 14 字总体证据门槛），可定位到句／分句边界，不能靠单独短语、短对白、跳过正文字符或全章相似度凑足。检测可保守地拒绝有明确边界证据的候选；除原先安全的整段首尾剥离外，不在入库前自动截掉部分句。旧段的开头在候选首部复述，即使旧段还有多句尾文，也在此规则内；两次候选用完全相同的校验。

命中或仅剩回声时，在同一次 `insert` 内清除旧预览，带结构化问题反馈定向重生成同一个块一次。重试前重新检查取消、章及大纲版本、锚点和实际派发证据；修正流也须完整并重新验收，不能递归重试。输出触限不走质量重试；既有不完整流恢复不扩展到修正请求。以同 Run 的章／位置及快照防止主 Agent 原样重发规避预算，不把质量失败缓存成「该章任何合法位置都不能再写」。两次都失败不调用该处的正文／大纲提交，也不产生片段回执或同步进度；其他已提交的内容不回滚。通过之后才按既有路径进行提交、记录实际片段和发起必要资料同步；磁盘 I/O 故障仍按现有实际提交和部分提交语义处理。

### 2. 正文定点修订是独立工具，不把整块正文加回资料工具

只在绑定小说的 Harness 注册 `book_patch_chapter`。接口为 `{ chapterId, revision, edits: [{ quote, replacement }], evidence? }`；自修使用 `evidence` 给出来源章 ID、读到的当前版本和短原文。普通定点修订有事实来源时也可提供并加版本保护。复用 `book_get_context` 的定向章节读取，确保能读到用于匹配的完整短文和实际版本，不将截断的预览当原文，不要求扫全书。服务端校验目标与本 Run 已读取版本相符，再按同一现稿逐项精确定位；不对锚点作模糊归一化。空旧文、缺失／多义命中、交叠、无实际变化或明显越界的修改均拒绝整批。支持明确的局部删除（空 `replacement`），不支持空锚点插入或用大量补丁拟装覆盖；新增场景仍走 `insert`。

初始边界：单次最多 3 处，每处旧文和新文各不超过 600 个 UTF-16 代码单元，总旧文和总新文各不超过 1,200，变更旧文合计至多占目标正文去首尾空白后的三分之一；同一 Run 同一章最多一次成功提交，必要的多处同时校验。按原正文中确定的范围一次合成，除了目标片段（包括用户明确指定的片段内换行）其余字节、章节字段、大纲及其他资料不变。使用现有工作区 `writeChanges` 路径，在提交时按 `revision`、适用来源版本和取消状态再次校验；不逐个片段先写再校验。回执只列定位标识、原因、实际修改数量及已提交章节版本；锚点失效可在原授权仍成立时定向重读，不能通过换工具回避。通用资料工具继续拒绝传入章节正文，改用可辨别原因和正确的工具引导。

### 3. 由后端判定权限；语义检查不能创造权限

| 调用情形 | 判定依据 |
| --- | --- |
| 当前作者明确要求局部改稿 | 从最新作者消息（及明确的编辑器选中章指代）解析目标章节和定点意图。仅改变明确指示的内容；能读到版本只是提交前提，不是授权。目标歧义、仅讨论、明确禁止、只有续写或增补意图时不执行。 |
| 正常整书 Run 在交付前修正自身事实矛盾 | 后端保留 Run 启动时的空白／缺失状态与工作区实际 `draft` 提交回执，证明目标在登记范围、从空白确实写到盘上、现稿仍是该次提交版本、本轮未禁止修稿。复用稿、其他 Run 的作品和被作者或外部修改的稿件不享有隐式自修权限。记录仅在本 Run 有效，不能靠历史或重启恢复授权。 |
| 单纯增补授权，或执行已确认的增补方案 | 不获普通正文补丁权限；仅能按下节清理活动 Run 在当前有效范围内实际写入的新增片段。 |
| 仅续接、模型安排或要求重写 | 这几类本身均不授权定点修订，也不能继承旧 Run 的回声清理权。`replace` 仍走原授权检查；输出触限的逐项恢复不扩大写入类型或专门触发自修。 |

整书自修还需至少一条能在已保存前文章中核实的直接证据。服务端先核对来源章、版本、精确证据及故事时间顺序，再使用有界的工具内核验，只看已核实的证据和拟改的旧／新片段，判断是否为基于同一事件的明确纠错，且未增加证据不支持的剧情。此核验只有通过、拒绝和不可核验，不能另写正文、扩大目标、调用工具或变更权限；拒绝、超时、格式错误或不确定都不写入。使用现有模型请求路径和预算约束，不引入独立 Agent，不要求每章固定审校。显式定点改稿由作者指令限定，不能因存在证据就生出隐式修改其他章的权利。

主 Agent 根据已知问题按需行动：例如保留第 8 章现场，只修第 10 章已明确矛盾的伤因；没有现稿依据的脱身经过单独列为待定剧情。整书进度继续以已保存章数和原有资产要求核对；修订结果另以真实回执汇报。「10/10 章已保存」不等同「已解决所有一致性问题」。

### 4. 以插入回执约束的同 Run 回声清理

保留 `book_patch_chapter` 的现有授权，不增加可由模型自报的授权参数。新增独立 `book_clean_insert_echo`：只收目标章 ID、当前章 `revision` 和工具返回的 `insertionRef`，不收原文锚点、范围、删除文本或替换稿。仅当作者未禁止清理且本 Run 的直接增补／确认方案仍允许该位置时可用；规划、只读、逐项恢复及跨 Run、跨会话或重启后不能从历史回执取得此权。主 Agent 发现漏网回声时可尝试一次，不增加固定审校，也不用为此请求通用修改权限。

每次实际成功的插入记录内部版本链、片段原文偏移、长度和摘要，以及原锚点邻段的核验信息；没有资料依赖的单独插入也要有可核验回执。先匹配同作品、同会话、同 Run 的实际提交及当前活动范围，再核对该章仍是该次插入提交修订、片段范围和摘要吻合。本期只清理该章仍处于对应提交版本的片段；后来再次增补、人工或外部修改导致版本不符时，不猜偏移、不尝试以新修订重新获取隐式权限。部分提交不能冒充完整插入回执；原先另有关联大纲的，须该次正文及大纲均实际成功。

服务端重新计算明确的相邻旧文回声，为自动删除选出唯一、安全的原文区间：只在该新增片段首尾，匹配连续复制字词，可包含明确属于重复部分的相邻标点和分隔空白；截在可核验的完整句／分句边界，留下非空新增内容，不能吞掉下一处新动作的起始字，也不能跨过原稿切片。绿灯侠形态须能删除整段重复开头并从原有的「他把……」动作继续；不能删除归一化公共前缀中偶合的新句首字。候选预检负责拒绝可疑边界；已提交稿清理需要更强的删除范围证明，若区间歧义、无法定位、无新内容或会破坏 Markdown 结构则零写入。不调用模型生成正文，不改旧锚点，不用整章重写或通用补丁作后备。

在工作区共享写入路径下复核取消、当前章修订和实际使用的前提，预先验证受影响片段及同步记录能安全重定位。提交后以实际新章 revision 登记清理回执；更新被清理片段范围／摘要、同章受位移影响的片段索引及确认方案的最新版本视图，不篡改旧提交历史，也不能把清理当作第二次插入或恢复已消费的权限。回执标识、章版本、是否需要同步及可定位原因足够，不回传文本。重复提交不写第二次。

同步不得把旧版源证据当作新版本成功依据。若对依赖该片段的已同步证据能逐一验证引用不受删除影响、仍可在同一保留片段唯一定位且资料版本未变，可以更新核验依据而不重写资料；否则将仅受影响且仍授权同步的项目标成待同步、使用现有资料工具重新核验及必要同步；若无法维护同步一致性且不具备有效同步范围，应在提交前拒绝清理。清理调用本身不写大纲或资料。还待同步或清理失败时准确区分「增补已保存」「回声已清理」「仍有问题或待同步」；`8/8` 不当作质量证明。

### 5. 诊断记录原因，不记录文本

让候选质量拒绝与断流、超限、锚点／版本冲突可区分，并能关联首次生成、至多一次的修正及实际提交。对正文定点修订区分未授权、版本冲突、锚点或范围不符、证据不足与成功；记录边界重叠的安全类别，以及同 Run 清理与原插入回执的关联、拒绝原因、新提交和同步复核结果。通用工具的正文误用不要淹没在 `tool_failed`。添加到现有诊断和回执允许列表，只存安全原因、标识、计数等必要元数据，不存原文、替换文本、来源摘录、模型响应或提示词。

## Risks / Trade-offs

- **误判有意重复或漏过较隐晦的串稿** → 先用可控的句段检测与明确的稿外信号；保留安全样本作回归。疑似结果宁可让 Agent 报告该处未写，也不自动改旧文。
- **一次修正请求增加延时；语义核验也可能判断错误** → 只在有问题的插入或主动提交的整书勘误上请求；限制预算、默认失败不写。不承诺检测所有连续性问题。
- **修订与人工编辑并发** → 不从新版本自动续写旧补丁；提交阶段守住目标和来源版本，保留手工编辑及未保存草稿的现有冲突行为。
- **短章或大幅修改被局部预算拒绝** → 明示是范围问题，不建议 Agent 拆成绕过限制的小批；需作者决定缩小改动还是授权重写。

- **清理后旧同步证据失效** → 用版本、片段范围和引用一致性校验，不把旧回执静默标成新版本完成；受影响的任务回到原授权下的待同步。

## Migration Plan

无数据迁移。随后台工具和内置 Skill 一起发布，复用现有文档和写入回执；可兼容地追加清理回执，但既有历史记录不能成为新权限。不自动清理先前的作品，回滚不恢复已清理的回声或撤销其他合法提交。

## Open Questions

无实施阻塞项。通过绿灯侠用例派生的确定性正反夹具和实际供应商复测校准边界判定；未知、歧义或超出可重复验证的信号不扩大为全章清理。

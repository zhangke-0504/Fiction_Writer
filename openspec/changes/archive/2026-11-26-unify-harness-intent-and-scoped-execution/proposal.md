## Why

人工验证暴露了同一职责错位的两端：后台在首次主模型请求前用作者措辞选定「关联增补」流程，写入工具又只按当前一句匹配授权，拒绝了主 Agent 根据同会话上下文发起的续办写入。变更要先恢复阻塞的续办能力，同时让主 Agent 成为唯一的任务意图入口，不再依赖关键词特判或固定工作流；MVP 不延伸权限与安全体系建设。

## What Changes

- 在同一个 Harness Agent 循环里理解当前作者消息和会话上下文，并按需通过 `tool_search` 或现有 `skill_search` / `skill_load` 发现能力。作品与普通目录共享发现机制，各自只暴露可用工具。
- 按一个 change、两个里程碑推进：P0 贯通同会话续办、局部修订、定点插入、既有资料更新和结果核对；P1 迁移直接关联增补并收口其他自然语言预分流。两者共享同一个执行契约，P0 不创建续办专用模式。
- 当前作者可以用清晰的同会话指代直接执行，无须复述章节、名称、参数或再批准。工具按当前有效范围校验动作、目标、版本、锚点、引用和真实提交；不把待办、回执、模型提议或参考数据当成授权。
- 章节记忆由主 Agent 按需发现并调用现有 `book_memory_recall`；取消首轮请求前根据作者措辞猜章和自动注入正文。保留按明确目标章取材的能力，不新增独立意图工具或中转流程。
- 记住、更正、忘记长期约定由主 Agent 理解并调用工具；移除工具内部的意图正则和本轮原话逐字包含校验，不为此增加审批、注册范围或额外模型核验。
- 实际删除旧的直接增补词匹配、章序三等分分流和无 scope 兼容路径中对应的实现；直接删除只验证旧分流的测试，保留实际增补、同步、冲突和自然语言续办的功能回归。
- 修复新插入路径暴露的「黑寡妇」回归：作者在同会话回复「补上对决」时，应能直接复用已有角色与伏笔定点插入正文，不需要本轮新建资料、先改目录或授权整章重写。按真实资料 ID 校验引用；本轮创建记录只用于后续新资料同步。
- 取消同一 Run 对同一章只能成功提交一次局部补丁的限制。Agent 重读现稿后可以继续修；搬移等相互依赖的改动优先一起保存，分步时分别核对删除旧段和补入新段，不增加审批。
- 让已登记的写作任务（包括自然语言续办和资料同步）接入已有的主 Agent 输出触限恢复。从当前剩余项、现稿修订和实际提交回执提供一个可独立核对的小步，由 Agent 选择现有工具；不改变预算档位，不恢复旧审批或关键词分流。
- 修复 `BookTaskScope` 迁移后整书目标未接到写章工具的回归。主 Agent 通过现有工具登记完整目标，或在作者明确要求续写时承接同书同会话的目标；整书正文请求按已激活的目标使用既有长写作档，不因只登记单章动作而降到标准档。不改预算常量，不新增关键词分流、审批或固定流程。
- 分开记录 Run 终态和业务完成度。一次正文提交只证明已落盘的那部分，不代表复合任务完成。显示真实的已处理、未完成及客观阻碍；已满足的事项可凭读回复用，不重放旧写入。关联增补进度不再在主 Agent 解释请求前出现。
- 把「黄灯侠」真实供应商端到端流程作为发布门槛，通过应用接口和 Playwright Electron 等程序化方式验证，不使用 Computer Use：专用测试作品按同名清场规则创建，生成十章约 50 字的微型场景（基线 3 个人物主体、1 条伏笔）、直接增补反派、有遗漏则用自然语言续办；若整书写作确实中断，可在同会话发「继续」，逐轮核对落盘并在无进展时停止，不用重试掩盖整书选档回归。核对磁盘、回执和叙事约束，不以模型总结或进度数字替代验收。另用受控「黑寡妇」场景覆盖只引用既有资料而不新建角色的情况，两条回归互补。

## Capabilities

### New Capabilities

无；在现有 Harness 和写作能力中实现。

### Modified Capabilities

- `background-agent-harness`：统一任务入口和工具发现，改为按需召回和直接操作长期约定，明确跨轮指代、执行范围及独立的任务完成结果，让正式写作范围接入已有的同 Run 触限续接。
- `novel-writing-workflows`：允许按当前指令的同会话指代做有界写入；移除旧关联增补分流，由 Agent 根据作品的剧情而非章序决定位置，支持使用既有资料补写场景，保留插入、局部修订、关联同步与事实勘误的边界；触限后以现稿和实际回执逐项推进，不缩减原任务；整书登记和自然语言续写均把有效目标传给写章工具。
- `local-diagnostic-logging`：让能力发现、显式记忆召回、写入结果和业务完成度可关联，不再要求 Agent 首轮前自动召回的诊断；复用现有事件区分目标未就绪、主 Agent 与写章子请求的实发预算、触限、实际续接与提交。

## Impact

- 影响后台 Run 入口、主 Agent 循环、能力注册、会话/回执和小说工具，及 Harness 的任务进度与结果显示；需覆盖正文、资料、大纲、整书续接和普通目录等现有路径。
- 不引入审批、额外授权框架、任务子 Agent、提供方依赖或第二套工作流；不变更作品文件格式、书内记忆隔离与普通目录工具。

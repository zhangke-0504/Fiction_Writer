## Goals / Non-Goals

**Goals:**

- 同一个主 Agent 结合本轮作者消息、同会话历史、当前选中项和实际作品决定行动；正常写作、直接增补和后续修复走同一个循环。
- 小说与普通目录共用能力发现；记忆读取和长期约定维护由主 Agent 选择工具，正文和资料变更继续核对文档目标、版本及实际落盘，不让 MVP 变成权限系统建设。
- P0 优先解除续办阻塞；P1 去掉关联增补的自然语言预分流并收口相关路径。两阶段共享契约，最终验收既保留「黄灯侠」真实供应商端到端，也覆盖「黑寡妇」在同会话只用既有资料补戏。

**Non-Goals:**

- 不为「未清理的问题」、黄灯侠、特定章号、反派任务或指定提供方加产品分支；不添加任务模式、小说阶段机、审批弹窗、通用写入旁路、单独的意图 Agent 或固定工具顺序。
- 权限与安全体系留到产品后期。本次不增加权限模型、逐动作审批、语义审查层或原文证明流程；不是删掉书绑定、文档 ID、版本和锚点等让功能正确运行的校验。
- 不做扩展市场、向量检索、大规模会话存储迁移或独立计划审批系统。局部复用现有方案、回执和输出上限恢复机制；不改 Markdown 作品格式。

## Decisions

### 1. 让能力发现留在主 Agent 循环内

`startSession` 做绑定和输入校验、创建 Run、提供稳定基础指令及上下文，不在首次主模型请求前用措辞选任务或发布任务专属进度。把保存方案、选中项和参考数据按来源标明。首次主模型请求前既不按词强制指定业务工具，也不猜测目标章或自动检索、注入作品记忆。

`tool_search` 由当前 `LocalTool` 注册信息和会话可用性派生，返回稳定 ID、用途、读写性质及可调用参数说明。首轮提供轻量发现入口及必要公共控制能力；新发现工具的真实 schema 在后续请求中可用，保留 Run 内已发现的工具用于后续调用。小说复用 `skill_search` / `skill_load`，普通目录不会得到书工具或小说 Skill。模型可改写查询、复用本 Run 已发现能力或根据明确的用户能力选择跳过重复检索；纯对话无需检索。搜索名称、别名、词项、排序可用规则，但搜索由 Agent 发起且结果并不选任务或扩大权限。接入现有轮次预算、参数验证、供应商适配与诊断，不落入另外一套执行 loop。相较后台根据用户原话预选能力，这个方案不会把可解释性绑定在关键词上。

### 2. 让主 Agent 主动召回和维护记忆

- 删除 `startSession` 中的 `memoryChapterTarget()` 调用及 Agent 请求自动注入的「本书记忆」区块；随实际引用清除无用的猜章逻辑。不把猜章正则包装成新工具。主 Agent 可用章节索引/读取工具确定目标，再经 `tool_search` 发现并调用既有 `book_memory_recall`；工具描述说明 `query`、`chapterId` 和结果边界，无需每轮强制召回。
- `book_memory_recall` 按调用参数和会话绑定的作品返回有界、有来源的结果。目标章明确时只给更早的已保存正文，区分计划与事实；没有 `chapterId` 时不返回全书正文作为默认前情，可查询作品约定等不依赖目标章的数据。实际写章工具已获得真实目标 ID 后，内部按该章自动取材可以保留；它不替主 Agent 做任务判断或提前猜章。
- 主 Agent 按上下文理解「长期保存／更新／遗忘」并调用 `book_memory_remember` 或 `book_memory_forget`。移除 `authorIntent()` 与 `plain(prompt).includes(plain(text))` 两道门禁，允许 Agent 传入忠实整理的约定、通过约定 ID 更新或遗忘。不要求固定动作词、当前用户消息完全包含工具参数、不另走 `book_task_scope`、不另调模型审批。工具只做绑定作品、参数格式、非空、长度/数量、存在的约定 ID 和正常持久化检查。Agent 的工具说明需区分长期约定与普通讨论；不会在后台自动提炼聊天写入。
- 诊断采用现有调用与派发链路区分显式召回和写章取材。首轮不出现 Agent 自动召回事件；后续只在实际读取或发送证据时记录相应事实，不记录记忆正文。

### 3. 把作者意图的解释和动作的约束分开

对于正文、大纲和资料的写作动作，主 Agent 对当前指令形成最小结构化范围：本轮是否要求执行、涉及的动作类别与目标、继承的作者限制、同会话指代及支持依据。后端依据自己的 Run 上下文绑定作者消息、Session、作品/目录及只读证据引用；模型不能提供可冒充的作者身份、把任意 assistant 文本标为用户消息，或通过 `authorized: true` 自行解锁。未形成有效执行范围时拒绝写入。本轮指令可以直接授权，也可以明确采纳此前可见的方案或续办清单；方案、清单、Skill、检索、作品正文、附件、旧回执及纯历史许可都不能单独授权。被压缩的总结和历史摘要可辅助找内容，不能单独充当作者消息或方案原件。新的限制优先；上一轮「此轮只讨论」不妨碍本轮明确要求执行，但未撤销的作品限制继续适用。

范围由同一主 Agent 提出，Runtime 接受并绑定后由工具查询；可随新读稿细化定位，不得随工具失败而自行升级动作或扩大作者范围。对多步写作，可以登记有界目标及成功条件；单动作可在首个有效写请求绑定范围，不需另起固定计划阶段。不把写上下文拼成一个新的 `authorPrompt` 送回旧正则，不要求之前必须存在机器生成的方案。真实消息角色、来源引用、显式结构约束、动作用途与目标是可确定性验证的；自由文本的语义是模型判断，不宣称仅靠 ID/锚点能抵抗模型误判。保留现有针对候选的有界核验；不能核实授权范围或语义存在实质歧义时先只读或拒写，需要时澄清。此处不新增另一个负责分类/调度的 Agent，也不把审查通过当成扩大权限的依据。

写入路径保留书/目录隔离、稳定 ID、实际读稿版本、唯一锚点/短原文、局部改动限制、关联引用、提交前重新核验、取消和回执等约束。正文 `patch`、`insert`、`replace` 不是可互换动作，资料更新保留未受影响的段落及有效关系。子请求只取本动作的作者要求、范围和版本化证据，不继承整个会话，也不自动触发另一项生成。原有显式命令语法、版本保护、插入质量复核和抑制重复保留；旧 Run 插入回执不授予清理权限，事实勘误仍只适用于符合原条件的同 Run 新稿。

### 4. 把关联增补迁成普通的组合任务

实际移除旧的 `prepareEdit()` 直接增补入口、`stagedEntry` / `connectedEntry` 的按措辞选择、固定 `0/5`、章数三等分以及只为旧直接增补遗留的无 scope 分支；不留仅供测试调用的旁路。若 `connectedEntry` 等代码仍承载基于结构化动作的同步，应保留或改名，而不是把证据同步一并删除。删除专门期待旧路由、固定章区间或固定计数的测试；混合覆盖拆出真实回归，保留实际插入、主体关系、同步、冲突和续办断言。主 Agent 读完大纲和相关章节后，按作者目标分解可独立定位的正文、资料和大纲动作。对本次反派需求，区分「中期迹象」「后期首次实际登场」「计划回收」「实际回收」；章节位置由剧情与作者约束确定，数量与阶段条件来自本轮有效范围，不是常量。底层可保留按已提交片段核验关联、定位冲突、同步本次新资料及守护大纲版本的通用机制。不是把同一组固定步骤搬到 Skill 或 prompt；没有单处失败必须使所有其他动作无效的业务规定。

顺带审计 `prepareEdit()`、`approved/confirmed`、增补位置、重写、章数、整书续接以及资料更新的所有相关调用点。保留显式计划引用、结构化章数与目标列表验证、历史方案和续接记录的来源校验，而不是从词匹配获得权限。普通目录继续用其原有文件与命令边界，只迁移发现，不注入小说能力。

### 5. 插入可使用既有资料，创建记录只用于同步

`BookTaskScope` 的 `stage=setup/reveal/addition` 描述片段的剧情作用，不是进入新角色工作流的开关。`book_generate_chapter` 使用已有的当前作品引用检查来解析调用中的 `subjectIds` / `clueIds`；真实、可用于本场景的既有卡片与本轮新建卡片同样可作证据。不得以 `createdHere` 的成员资格、资料创建时间、目录字段中是否预先挂上关联来阻挡插入。`createdHere` 或同等回执集合只标记哪些本轮新建资料可进入后续同步，不因复用已有资料而自动更新它们。非法或不存在的引用仍按具体 ID 报错，继续保留章节版本、唯一锚点和按剧情可披露内容的校验。

现稿大纲已描述目标场景时直接使用；只有确需调整大纲且在当前任务内，才附有版本的局部 `outline` 更新。不要求为了满足 `stage` 而追加重复大纲、重贴角色关联、建空卡或尝试整章 `replace`。错误回执应指出能纠正的具体前提（例如哪个 ID 缺失、哪个版本变化），而不是把真实旧资料报成缺失。本修复走原有定点 `insert`；不依赖放行 `patch`，也不据此重做整个补丁审批机制。

### 6. 同章可继续修订，搬移优先一次保存

[「黄灯侠」复验](verification.md)中，第七章只提交了旧对话的第一处删除，后续补丁被 `patchedHere` 拦截，任务却显示 `fulfilled 1/1`。这是两个独立问题：按章限制成功次数挡住了后续写入；按「动作类型＋文档」计完成，又把第一次写入误算为整个搬移完成。

移除 `patchedHere` 及等价的按 Run、按章次数门禁。后续修订以重新读取的当前版本和唯一短原文定位；保留单批局部范围、批内不重叠、取消和提交时的版本检查。旧版本或锚点已失效时返回实际冲突，不自动重放旧补丁，也不通过连续补丁变相重写整章。

章内搬移优先复用 `book_patch_chapter` 的同批编辑：一处删除旧段，另一处保留目标锚点并补入对话。两处基于同一现稿校验，都通过才一起保存；任一处不成立时当批不写。确需分步时，Agent 可以在同一 Run 重读现稿后继续，无须作者再发指令或再批准。无需专用搬移流程或额外模型审批。

复用任务记录和回执，区分同章中可分别核对的子目标，即使都走 `chapter.patch`。提交只为它实际覆盖且可核对的子目标提供证据。不因一个目标先提交就把其余同章目标结清；只删未补时保留已提交修改，标为 `partial` 并列出待补入项。已满足的子目标可以用读回证据结清。目录和大纲变更不替代正文；必要同步仍单独核对。

### 7. 以任务项和真实回执判定业务完成

对需要延续的任务，用当前可见待办、实际回执和现稿重建最小工作集合。有必要持久化时仅追加有界任务项、来源引用、状态和提交引用，且不是权限票据。重启/改版后不自动恢复写入或重放旧参数；在本轮作者指令下重新读稿、跳过已满足目标，重定位实际待办。摘要/历史不足时不猜，不要求用户逐项批准；可以按安全范围处理明确项并指出歧义项。

Run 的 transport/lifecycle 正常结束与任务结果是两回事；对任务区分完成、读回已满足无需写入、部分完成、未完成；取消、中断和没有任务的纯会话单独处理。已执行目标从对应动作回执与必要读回核对；正文插入只有确认正文实际新增才能计为该目标完成，目录关联字段或单独大纲的提交不替代它。有失败但后来合法修复不误记未完成；零提交且问题仍在不记完成。诊断采用白名单内事件、ID、计数和原因，串联首轮请求、发现、候选调用、范围检查、提交和结果，不保存作者措辞、查询内容、工具原始参数或稿件。

### 8. 用正式任务范围接入已有的触限续接

- 在现有 `narrowedWritingStep()` / `runAgent` 路径接入 `BookTaskScope`，根据本 Run 仍有效的动作、目标及子目标（含所需同步）、已读版本和实际提交回执计算剩余项。跳过现稿已核对满足、或有效提交已满足的项；已列入范围的文档 ID 本身不证明内容已经读过或更新。旧整书恢复保持原行为；正式续办不依赖 `ConfirmedBookEdit`、旧确认入口或再次问作者。
- 从最后一次有效上下文给 Agent 一个足够小的候选范围。已有当前版本证据时，可以只更新一条待同步资料；缺必要信息时，只提供一个和待办直接相关的定向读取，例如读取一个目标文档的当前修订或必要片段。Agent 仍用现有工具的 schema 自己选择动作和组织参数，Harness 只校验调用没有越出这一步的范围；不根据作者措辞或截断参数猜工具，不自动替 Agent 调用工具。一次调用内也不能打包多个可独立完成的待办；原工具要求原子保存的改动仍不拆坏，必要时如实停止。
- 沿用现有 Messages 明确触限处理：不执行或回放半截批次，同 Run、同逻辑轮、原模型和原有效输出额度只额外派发一次，且与坏 JSON 恢复共享同轮重试限制。成功后保留逐项处理，根据每次读取或提交更新候选，直到原范围满足或无法推进。若无可定位小步、必要输入放不下、取消、再次触限或无进展，沿用原终态并保留实际成果；不扩大范围、不重放已完成的写入、不把单步成功当作全部完成。不给此次恢复新增审批、语义复核、预算档或工作流。

### 9. 让整书登记和续写共用同一目标

- 主 Agent 继续理解作者对整书或前一未完成整书任务的指向，按需发现、加载 `generate-novel`；只将实际送达并生效的整书 Skill、当前已登记的整书动作及通过现有工具激活的目标用于整书路径。检索候选、历史中曾加载 Skill、仅有空白章或孤立的「继续」都不能自行触发整书写入，也不把检查当作额外审批。不恢复按措辞预分流，不在首个模型请求前建任务。
- 对当前整书执行，复用 `book_task_scope` 的 `novel.register` / `novel.resume` 和 `book_get_context.novelGoal` 的 `register` / `resume`：前者表达本轮整书动作，后者核对并激活有序章节 ID 和所需资料。两者不能由若干 `chapter.draft` 项替代。恢复 `requireGoal()` 对当前已生效整书任务的前提校验：没有活动目标时把现有 `novel_goal_required` 和下一步交给 Agent，不走普通单章正文请求；只读和登记仍可用。同步现有 Skill、工具 schema/说明及必要的纠正反馈，不加新工具、语义分类器或编排阶段。
- 作者在同书同会话明确继续时，已有有效记录就恢复原目标并用现稿、回执核对缺项；如果旧 Run 从未成功登记，且原整书要求、章数、顺序与现稿仍可从同会话核实，则由 Agent 通过现有 `register` 补建完整目标，复用现有章 ID 和已落盘稿。既不伪造 `resume` 记录，也不把只剩未写章节重新当作一个较小的整书目标。已有记录但未完成时不另开一个目标替代；缺证据或有冲突时给出可定位结果，不猜、不覆盖，不要求作者复述能够从同会话核对的信息。
- 实际属于该活动整书目标的写章子请求使用现有 `long-writing` 预算规划，仍按供应商能力约束；主 Agent 加载时的先行选档不能当成子请求已经提档的证据。真实单章任务保持原行为；不改档位常量、模型超时、写章失败不落盘规则或主 Agent 同 Run 触限恢复次数。作者发「继续」会创建正常的新 Run，不是 Harness 自动重开 Run。

## Risks / Trade-offs

- 只删门禁或把线程历史拼成长字符串再匹配 → 逐工具迁移并用「先分析，别动稿」、只准插入、无关历史/附件和越界参数回归；既测试固定模型响应下的机械拒绝，也测试真实语义路径。
- scope 变成适用于所有请求的复杂强制计划 → 按动作最小绑定，任务清单面向续办和进度，不能授予权限；不引入固定站点或额外确认。
- 动态能力影响供应商 schema、预算或输出上限恢复 → 搜索结果有界，模型只看到所需 schema；回归所有接入的请求组装、校验、单步缩小和取消。不能用提高循环/模型上限掩盖问题。
- 原日志中的合法写入之后还可能遇到容量、内容质量、版本冲突或资料条件 → 在授权范围内调整候选并查回结果；仍存在的真实阻塞如实标为未完成，而不是把「正确报告失败」算成发布验收通过。

## Migration Plan

1. **P0**：新增共享的 Run 范围与能力发现最小入口；先接入局部修订、定点插入、资料更新，移除这些迁移路径上的单句措辞门禁并验证任务结果。先跑受控续办回归；不存在以自然语言特判实现的临时兜底。
2. **P1**：迁移关联增补和其余已审计的自然语言预分流调用点，保持确认方案、整书续接及普通目录兼容；完成受控全链路、同义句和非等分剧情回归，然后跑下方真实验收。
3. **MVP 收口**：完成记忆和增补清理，解除同章后续补丁限制并修复复合任务误报。让正式任务范围接上触限单步续接，修复整书目标登记与写章衔接。先跑「黑寡妇」、第七章搬移、正式 Harness 路径的受控 Messages 触限回归和整书登记／续写选档回归，再在最终实现上重跑「黄灯侠」真实验收。
4. 已有作品、会话计划和回执按原版本读取；新增结构采用可选、兼容字段。回退实现时保留已经落盘的作品，不自动还原旧稿或从旧回执重放。

### 最终端到端验收（真实供应商）：黄灯侠

通过程序化接口与虚拟浏览器/渲染器验收，**不用 Computer Use、桌面鼠标键盘自动化或基于截图点击**。优先复用现有 Playwright Electron 测试：用 `FW_E2E=1` 和专用 `FW_TEST_ROOT` 启动真实应用、使用隐藏测试窗口；通过页面上下文的 `window.fw.request` 调用应用 IPC，必要时用 DOM 定位器验证 Harness 展示。用真实已配置的模型供应商，不打桩模型。用应用状态、事件或有界轮询等待 Run 终态，不靠固定睡眠或盯图判断。测试脚本只负责建书、发送原始作者消息、等待和断言，不代替 Agent 调书内工具、注入计划或直接修改待验稿件。

在隔离测试库按精确书名查找「黄灯侠」，存在则核对其 Book ID 位于本次测试根，再调用 `book.delete`；禁止在真实创作库清场。随后通过 `book.create` 新建同名小说，简介精确为「基于DC漫画七灯军团里的黄灯来写的故事」。清场是测试准备，不是 Harness 业务步骤，也不是本提案起草动作。

1. 建立该作品的 Harness 会话，通过 `session.start`（或 Playwright 渲染器中的正常提交入口）发送 `根据设定编写10章内容。每章正文约50个汉字，写成一个有情节推进的微型场景，不要写成梗概。整书只建3个人物主体和1条有埋设与回收的伏笔，不建物品、地点等额外主体。大纲每章一句，人物卡和伏笔说明各保持简短。`。这是缩尺验收输入，约 50 字为写作目标，测试用非空且不超过 100 个非空白 Unicode 字符防止回到长稿；该约束不限制真实创作或后续增补的篇幅。正常流程预期本 Run 完成。若实际触限或中断且仍有明确缺项，可在同一会话只发「继续」或同义指令，不新建书、不补章号或工具参数。每轮读回新落盘和旧稿修订，有进展才继续，不无限重跑（连续两轮无进展即停，记录阻塞）；分别记载一次跑完和中断后续成。整书阶段须实际核对 10 章非空正文、大纲、所需主体与伏笔说明及有效引用。记录章 ID、顺序、基准修订和主 Agent／写章的实发预算；不得把标准档偶然写成几章当作整书衔接修复通过。
2. 在**同一个会话**输入 `增加一个跟2个以上人物主体有关联的反派吧，然后剧情中期增加一些该反派的线索，到了后期才抛头露面。你看看要怎么改，想好之后直接改就行，不需要找我确认`。核对不要求确认、首个主模型请求先于任务专属进度且未注入自动记忆、能力发现确实发生；同一反派与至少两个不同的已有主体有效关联，按剧情在中期实际落盘相关线索、到后期才实际登场，且相应大纲和资料同步与现稿一致；未经实际写出的回收保持为计划。原章 ID、顺序、范围外与未授权的已有正文不变。
3. 若这轮报告未清理事项、部分失败或读回复核发现其他尚未解决且与本任务有关的问题，留在同一个会话输入 `解决未清理的问题`，或语义等价的 `把上面那几项处理掉`。不手工补章号、锚点、工具名和再次授权；核对待办实际修复，或有现稿证据已满足，不重复已落盘事项，不扩大原范围。仍存在未解决的有效待办，或声称成功但现稿、版本/回执不支持，均不通过。若自然没有待办，记录本轮此步不适用；受控回归仍须真正覆盖带待办的第三轮。

长稿的登记前触限属于另一个 Harness 架构问题，日志和备选方案已经单独记录在 [Harness 反复触限调查](../../../../design/20261126/harness-context-budget-and-delegation.md)；本次只缩小验收输入，不改产品预算、工具或流程。短稿通过不代替长稿压力验证。

成功条件是整个适用流程在真实应用里顺利完成，核对磁盘和脱敏诊断，既不能由测试脚本指定业务工具序列来代替，也不能以模型摘要、运行正常终止、测试假模型通过或进度 `n/n` 代替。供应商或环境阻塞应记录并重测，未跑通之前不宣称发布验收完成。

若真实续办涉及段落搬移，读回对应章，分别核对旧段已从原位置移除、新位置已补入预期内容；仍缺任一部分或必要同步时，结构断言通过也不算通过。若真实运行没有搬移待办，不强制改造剧情，由第七章受控夹具覆盖：同批完整保存、任一锚点无效时整批不写、分步只完成一半时报 `partial`、重读新版后同 Run 继续完成。

用受控 Messages 响应从正式 Harness/IPC 入口确定性复现：新 `BookTaskScope` 有未同步资料与有效旧回执、没有整书 Skill 或旧确认方案，主 Agent 输出带写入工具的 `max_tokens` 终态。核对原批次零执行、同轮同预算只续接一次、必要时定向补读、合法单项真实落盘、其余任务继续按实际完成度报告；无候选或再次触限则保留已有提交并停止。真实验收用正常的供应商配置并记录实际能力来源与出站预算；若真实流程未触限，只证明正常流程通过，不能替代受控恢复回归。

另从正式 Harness/IPC 回归整书目标交接：整书指南已派发、只登记单章动作时，缺目标反馈可引导 Agent 完成登记，且未派发标准档正文请求；有效整书目标下的实际正文请求按 `long-writing` 规划。用有记录和从未登记的两份部分稿验证同会话「继续」或同义表达，核对保留目标范围、复用已写章节、只写剩余章。另对照明确的独立单章写作和只读请求，确认没有新门禁或不必要提档；以脱敏日志、模型夹具捕获的实际请求和磁盘稿件为准。

### 补充受控端到端回归：黑寡妇用既有资料补对决

在隔离测试库准备「黑寡妇」形态的十章现稿，已有娜塔莎、伊琳娜、毒针伏笔，且第九章大纲已有对决但正文缺场景；保留同会话可见的「保留悬念／补上对决」回复。通过正常 Harness 入口发送「补上对决」（另覆盖同义句），不在续办 Run 创建新的主体或伏笔，也不靠更新章节目录的关联字段通过校验。核对插入场景实际进入第九章正文、锚点两侧原文及其他章不变、不重复改已正确的大纲，落盘修订与插入回执一致。再注入一条不存在的引用或过期版本，确认错误可定位、正文零提交，不用元数据提交冒充正文进度。该用例不要求模型随机生成一份恰好缺对决的初稿。

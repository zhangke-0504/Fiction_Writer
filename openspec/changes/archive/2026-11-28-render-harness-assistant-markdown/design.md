## Context

`src/Harness.tsx` 的 `ChatMessage` 将各角色的消息正文插入同一个 `<p>`。`ChatTranscript` 用它渲染已保存的消息及展开的工具活动，`current.streaming` 也通过它显示。后台每次追加流式分片时提供累计文本，在提交一条 Agent 消息时清空该文本。旧确认方案的恢复逻辑会逐字核对已保存的方案正文。

## Goals / Non-Goals

**Goals**

- 让 Agent 的流式和历史回复使用同一套 Markdown 排版，并能直接显示旧会话中的回复。
- 在 Harness 窄栏内保持正文可读，延续对话消息的顺序、工具活动折叠和消息区跟随行为。

**Non-Goals**

网页跳转和图片预览属于独立交互。本次提供链接和图片说明的文本展示。

## Decisions

### 在 `ChatMessage` 的 Agent 正文分支渲染

使用 `react-markdown` 把原始字符串渲染为 React 元素，使用 `remark-gfm` 支持表格。已有的 CodeMirror 和 Lezer 分别负责编辑和语法位置解析。`remark-breaks` 将段落内的单换行显示为换行，使旧方案的说明和摘要保持分行。使用 Markdown 渲染器的默认 HTML 文本处理方式，将链接和图片映射为文本。链接展示标签与经过渲染器标准 URL 处理后可用的目标，同一文本只显示一次。图片展示替代文本。

### 使用现有流式快照和会话记录

每次更新使用当前累计的 Agent 正文作为解析输入。强调、链接或代码围栏跨分片时，后续快照可以重新解释整段文本。复用现有消息提交流程把临时正文交给历史记录渲染。按正文字符串对 Markdown 组件做记忆化，以便运行快照重新创建消息对象时复用已完成正文的渲染结果。渲染数据来自 `ChatLine.text` 或 `current.streaming`，JSONL 与后续上下文继续使用原始字符串。

### 将排版限定在 Agent 正文容器内

角色标签使用单独的样式选择器。正文的标题、段落、列表、引用和代码沿用 Harness 的颜色和紧凑间距。普通正文中的长字符串可换行，超宽表格和代码块使用各自的滚动容器，并复用消息区已有的纵向滚动和近底部跟随机制。

## Risks / Trade-offs

- 未闭合的 Markdown 在流式中间态可能暂时以标记形式显示。用分段本地响应验证收到闭合语法后自动重新排版，并覆盖流式正文转为历史消息的交接。
- 表格和代码块可能撑宽对话区。用最小窗口尺寸验证区块内滚动、消息区宽度和输入区可达性。
- 旧会话测试依赖所有消息正文都是直接子 `<p>`。按可见消息正文和工具摘要验证原有顺序，并用语义元素断言 Agent 的排版。

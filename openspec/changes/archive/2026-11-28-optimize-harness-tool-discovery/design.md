## Context

`discoverTools()` 根据本 Run 的可用工具定义构造目录。当前打分把名称、完整调用说明和顶层参数名拼起来，查找精确、子串和中文双字命中。许多说明同时提到前置读取、相邻入口和适用限制，交叉引用因此也会加分。搜索当前最多返回六项，并把每项的完整 schema 纳入后续请求。普通目录、绑定作品的主 Agent 和只读子任务各有实际工具目录，同一个 ID 在主、子目录中的定义也可能不同。 [tool-discovery.ts](../../../../electron/agent/tool-discovery.ts) · [worker.ts](../../../../electron/worker.ts) · [task-read-tools.ts](../../../../electron/agent/task-read-tools.ts)

设计记录中的段间空白案例在当前检出已将 `book_patch_chapter` 排首位。「查询文件中原文」仍把 `edit_file` 排在 `search_text` 前。「在现有章节插入一段过渡」把 `book_patch_chapter` 排在首位。「把人物卡里的归还计划改成已发生」漏掉了 `book_patch_asset`。目录缺少 `book_patch_asset` 时，精确查询还可能命中引用它的其他工具。 [调研文档](../../../../design/20261127/harness-tool-skill-discovery-optimization.md)

## Goals / Non-Goals

**Goals**

- 让短中文查询优先返回适用动作，使明确的工具 ID 对应当前目录中的定义。
- 让主 Agent 能通过已知注册名直接加载 Skill，并在名称不确定时查找候选。
- 用可重放的合成用例检验候选质量和整个 Run 的 schema 成本，为是否采用 BM25 留下可复核依据。

**Non-Goals**

- 自然语言意图路由、业务工具编排、写入授权、原文与修订核对属于现有主 Agent 和执行路径的职责。
- 方案范围是宿主内存中的检索和现有按需派发。外部检索服务、持久索引、额外工具协议和运行时模块加载属于独立议题。

## Decisions

### 在本地工具定义旁维护正向检索元数据

在 `LocalTool` 上增加可选的宿主侧 `discovery` 字段，记录简短正向用途及少量对象、动作别名。优先覆盖常用目录读取以及写入职责容易混淆的工具。例如，`book_patch_asset` 收录「人物卡」「伏笔说明」「短句定点替换」，`book_patch_chapter` 收录「已有原文」「段间空白」「删除多余换行」，`book_generate_chapter` 收录「起草空白章」「插入过渡」。同一工具可在一个字段中描述多个正向用途。名称、正向元数据和顶层参数名用于排序，完整调用说明及 JSON schema 继续服务于模型选用和提交参数。按当前工具实例构造检索记录，使相同 ID 的只读子定义能表达自己的用途。直接索引完整说明不需要补元数据，但会继续给交叉引用和否定条件中的词加分。

在初始预算估算及每轮请求裁配、派发边界使用由 `name`、`description`、`schema` 显式投影的 `ToolSpec`。宿主注册表仍关联可执行的 `LocalTool`。供应商序列化本来已挑选字段，但 TypeScript 类型声明不能裁去可枚举属性，`inputEstimate()` 会把传入的对象整体序列化。测试应验证检索元数据既未进入请求，也未靠虚增估算触发上下文裁配。 [local-tool.ts](../../../../electron/agent/local-tool.ts) · [context-budget.ts](../../../../electron/agent/context-budget.ts#L55) · [provider.ts](../../../../electron/agent/provider.ts#L121)

### 优先解析完整 ID，再对语言词排序

在 `tool_search` 内对查询做 NFKC、大小写和首尾空白归一化。明确的单个或多个完整工具 ID 按查询出现次序在当前目录中精确查找并去重，共享现有六项上限。只含 ID 的查询仅返回这些有效匹配。混合查询先取有效 ID，再用其余自然语言寻找候选。完整但当前不可用的 ID 也按整体处理，不把它的共有片段用作兜底。结果采用稳定排序，可为空。这样可以兼容现有批量 ID 查询，并避免把隐藏、未绑定或不存在的能力替换成别的工具。

`discoverTools()` 接受已经按 Run 或子任务组装好的目录。搜索仍返回稳定 ID、用途、读写性质和参数摘要，之后的请求才披露命中工具的真实 schema。实际可调用性取自当前轮发送的定义快照。普通同轮搜索与调用未披露定义、不同 Run 或子任务之间的披露隔离、Messages 参数重取的同轮定义快照，以及触限续接独立核实小步后额外披露的定义，都通过既有派发路径处理。 [批量 ID 夹具](../../../../tests/chapter-patch.test.ts#L266) · [请求裁配](../../../../electron/agent/loop.ts#L434) · [调用核对](../../../../electron/agent/loop.ts#L634)

### 用固定合成语料决定运行时排序

先用当前代码产生基线 A。B 使用正向元数据和现有词法计分，C 使用同一份元数据和分字段 BM25。B、C 共用精确 ID 规则，在自然语言子集比较排序。对三组使用同一批实际构造的普通目录、绑定作品和只读子目录，保存可复现的基线输出和查询预期。区分期望的动作、相关只读前置与无关候选，并留出一组未用来调元数据或权重的中文改写。覆盖只读、方案、资料定点修订、段间空白、正文插入、空白章起草、无命中、可用与不可用 ID 混合。`draft` 和 `insert` 的目标工具相同，具体动作由协议夹具核对参数。

BM25 试验优先给动作、别名和名称加权，简短用途其次，顶层参数名作为弱信号。可用 `Intl.Segmenter` 的中文词切分配合相邻汉字双字词，标识符字段可拆词用于自然语言匹配。只对当前目录计算词频与文档频率，可在首次搜索时建立本地索引。用校准集选择词权重、分词和候选截断规则，再用留出查询验证。对比目标进前三的比例、首个相关位次、无关候选数和新增 schema 数。采用 C 需要在关键混淆用例和留出集上相对 B 得到可重复的改善，并通过只读、空结果和目录边界回归。结合累计 schema 和请求成本记录取舍。证据不足时采用经过验证的 B。把数据、指标和决策记入验证记录。小目录中短别名可能已足够，直接切换 BM25 会失去判定元数据贡献的基线。

用脚本 Provider 和本地协议或 IPC 夹具核对请求中实际出现的 schema、首次正确调用、参数拒绝、搜索和重试次数、累计请求字节、输入 token 估算及本地耗时。schema 在发现后会随之后的请求重复携带，因此跨请求汇总。夹具衡量本地派发和脚本行为。供应商实际选用质量、延迟和计费需要独立测量。评测数据使用合成查询和工具定义，运行诊断用已有计数和派发事件。 [现有发现回归](../../../../tests/harness.test.ts#L231) · [派发指标](../../../../electron/agent/provider.ts#L498)

### 已知 Skill 注册名直接加载

整书提示已给出 `generate-novel`，引导 Agent 直接 `skill_load`，并将加载工具的描述与现有注册名 enum 对齐。Skill 搜索继续只返回有界文件头的名称和用途，有具体漏召时调整现有短别名。三项技能沿用当前排序，之后用目录规模和测量决定是否共用排序器。整书激活仍取决于本 Run 有效登记和指南已送达。首个合格指南结果在后续请求裁配前选择长写作预算，实际派发回调才记录已应用。只读子任务继续使用其自己的工具目录，写章工具内部仍按自己的路径加载 `write-chapter`。 [主提示](../../../../electron/worker.ts#L145) · [技能目录](../../../../electron/agent/skills.ts#L89) · [首个指南派发](../../../../electron/agent/loop.ts#L422)

## Risks / Trade-offs

- 中文别名贴合已知案例却漏掉改写 → 保留未参与调参的查询，并核对只读与写入动作的排序。
- 导入检索元数据后预算高估 → 初始估算、裁配和出站定义都使用明确的投影，并比较夹具中的实际请求。
- 额外命中使后续请求成本逐轮上升 → 比较新增 schema 数及全 Run 的累计估算，保留空结果与上限。
- 直接加载被误作指南已送达 → 回归覆盖同轮加载与激活、首次指南真正派发及受上下文压力阻断的请求。

## Migration Plan

先固定回放基线，实现元数据和精确查找，再用回放选定运行时计分。Skill 提示可以独立交付。目录状态仍随每个 Run 或子任务创建，工具请求、会话记录与作品文件沿用已有结构。出现排序回归时可回退到经验证的计分实现，已有会话按原读法恢复。

## Why

Writer 目前按固定的 64,000 窗口估算输入，对部分 DeepSeek 写作请求也只给 16,384 输出预算，既没有用上已配置模型的能力，也不适用于能力不同的端点。应由全局模型配置保存可用额度，再按请求分别计算输入和输出预算，为长篇写作提供更大的空间。

## What Changes

- 「新建配置」先进入供应商选择页。首版「模型厂商」只提供 DeepSeek；保留独立的「自定义配置」入口。两者复用现有表单；已保存配置直接编辑，不引入账号登录或远程模型下拉。
- 点「保存配置」自动识别已适配厂商的模型能力，并随全局配置持久化。首版适配官方 DeepSeek；查询失败按模型与端点选用兜底值，显示来源，仍可保存。新建小说、重启应用后直接复用；不增加能力检测按钮。
- 按模型能力和本次用途动态计算输入与出站输出额度，取代已知 DeepSeek 配置的固定 64,000 窗口和 16,384 大任务预算。供应商最大输出是上限，不是每轮都要用满的额度。
- 同一会话开始新一轮时，按供应商已确认的本次输入预算动态分配旧对话原文；只有未取得供应商额度时才保留 `9,800` 的兜底上限。不扩大跨会话记忆，也不改变总输入预算。
- 增加脱敏额度诊断，区分供应商声明、兜底、Writer 的请求策略和实际派发值。
- 本变更只调整供应商配置与预算基础：不修整书 Skill 首次派发时的预算选择顺序，不增加 `output_limit` 重试、续写或拆批，不改写入边界或 200 轮上限。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `background-agent-harness`: 增加供应商选择、保存时能力识别及持久化、兼容旧配置、统一的逐请求预算约束和动态的同会话旧对话原文保留额度。
- `local-diagnostic-logging`: 记录实际派发请求的输入估算、输出限额及其来源，不记录请求内容或密钥。

## Impact

- 设置页、模型配置 IPC 与全局存储、供应商适配器、主循环和写作子请求的预算与上下文装配、同会话历史保留、诊断及测试。
- 保持原有 API Key 加密、手填地址/模型 ID、协议发送路径与现有「测试连接与工具」行为；不增加运行时依赖。CC Switch 只作为本地 UI 与厂商目录设计参考。

## Context

`NovelTools.publish` 把整书正文核对和局部动作核对写到 `RunInfo.progress`。局部核对也会计入必要的资料同步。Harness 面板只要收到这个字段就渲染 `.writing-progress`，重开含该字段的旧会话时亦如此。当前状态行把有 `taskOutcome` 的正常终止统一显示为「本轮运行已结束」，局部待办则主要由进度卡显示。

## Goals / Non-Goals

**Goals**

- 一律撤掉任务进度卡，覆盖运行中、收尾和旧会话重开。新生成的系统状态和错误文案去掉固定比例。
- 在现有状态行显示已核对的结果、可定位的待办和阻碍。保留工具活动、运行状态、停止入口和失败诊断。
- 继续使用现有提交回执、目标核对和会话数据完成同会话续办。

**Non-Goals**

- 整书意图误登记的路由修复、生成能力调整和 Agent Todo List 均属独立变更。

## Decisions

### 移除唯一的进度卡渲染入口

删除 `Harness.tsx` 中由 `run.progress` 触发的 JSX 和 `styles.css` 中对应样式。整书和混合请求走同一界面，不再保留专用统计行。工具活动继续按已有规则折叠和展开，工具调用次数仍只描述该组活动。

### 在现有状态行呈现核对结果

运行中继续显示生命周期状态。运行终止后，用已保存的 `taskOutcome` 表达「已完成」「已满足，无需写入」「部分完成」或「未完成」。失败、取消和中断优先显示其运行状态及已有原因。已知的局部待办可从当前轮 `progress.local.remaining` 取得，使用已有的操作、目标和子项标识定位。条目有界时可提示还有其他剩余项，避免把截断视作待办完整清单。

混合任务按已核对的事实说明结果，例如「部分完成，整书已齐，伏笔『钟声』待更新」。若整书仍有缺项，沿用现有失败原因。新生成的整书及旧确认方案兼容路径的失败文案直接指出缺章、缺资料、无效关联或其他具体阻碍，去掉固定的 `X/N`。旧会话继续显示已保存的错误原文。使用现有结构化字段和阻碍文案，避免从 `progress.step`、会话标题或 Agent 回复推断结果。

### 保留会话数据和核对路径

`WorkProgress` 仍供后台核对、诊断和模型上下文使用。保留 `novelGoal.check`、各类提交回执、整书续接记录和 `local.remaining` 的既有用途。同会话续办仍以当前作者请求和现稿核对为准；新 Run 通过已有路径取得上轮剩余事项作为参考。旧会话直接沿用原有读写格式，无需迁移。

## Risks / Trade-offs

- 删卡后容易漏报部分交付 → 在已有状态行呈现实际阻碍和有界待办，复用混合交付和局部续办用例验证。
- 启动后过早断言卡片缺席可能让旧代码也通过 → 等后台已经发布 `run.progress`，再断言运行中和收尾的面板没有卡片。
- 历史记录可能只有计数或旧错误文案 → 保留原有错误和运行状态，任务结果只按已有结构化信息呈现。

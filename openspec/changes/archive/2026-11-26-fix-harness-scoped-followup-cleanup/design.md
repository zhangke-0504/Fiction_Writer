## Context

[一期归档验证](../archive/2026-11-26-bound-harness-tool-context/verification.md)记录了增补和同会话续办均只部分完成。续办有正文提交，没有人物卡的新提交；两个 Run 都观察到结果投影，未观察到输出触限恢复。依据本地 `design/20261126/harness-scoped-followup-cleanup.md`，同一个 `patch_scope` 错误可出现在多处；同一调用的独立审校请求证明候选进入审校，但文字长度及工具数不能证明原裁决是 `true`、`false` 还是无效。全文资料更新也仅能确定没有得到可接受的裁决，不能据此判定审校误判或候选确实越界。

## Goals / Non-Goals

**Goals:** 由同一个主 Agent 在当前作者的有效范围内续办：让正文补丁按既有结构化裁决处理；让有当前原文证据的资料短句直接定点替换；以实际提交与读回核对各项待办。

**Non-Goals:** 不改变一期投影、读稿送达、预算或触限恢复资格；不改变整书、同 Run 插入回声清理、新稿事实勘误、现有全文资料生成或同步规则。不增加模型复核、审批或工具沙箱，不开放通用资料覆写，不引入关键词路由或子代理。

## Decisions

### 1. 已登记的正文补丁以结构化审校裁决为准

- 只在 `novel-tools.ts` 进入 `reviewProsePatch` 的已登记 `BookTaskScope` 正文定点分支启用。审校仍看到当前作者指令、经核对的同会话范围及实际补丁，不能扩大授权。直接精确比对的旧路径、同 Run 新稿事实勘误及其他审校不改。
- 请求正常返回且未取消时，只接受恰好一个 `submit_chapter_patch_review` 调用及唯一布尔属性 `allowed`。`true` 允许进入现有提交检查；合法 `false` 是明确否决；缺失、多调用、错工具、错误 JSON 或不符 schema 是无效裁决；中断、超时或取消没有可用裁决。非空可见文字只用于诊断判定，不作授权、理由或业务内容，也不转给主 Agent。
- 继续检查登记的 `part`、锚点唯一与实际已读、目标及引用修订、取消和原子批次。已否决时提供安全、可操作的反馈，主 Agent 只可缩小至可独立验证的已登记项；不自动重试同一候选，不拆开必须一起提交的删除／补入。相比取消现有审校或靠自然语言解释判断，仅去掉无关的格式否决。

### 2. 独立的资料定点工具，共用一次范围登记

- 在绑定作品的 `tool_search` 注册 `book_patch_asset`，只在普通 scoped 写作中适用。工具参数为 `{ kind: 'subject' | 'clue', id, revision, quote, replacement }`，不接收 `body`、`fields`、批次、其他作品或创建／删除文档。活动整书目标与既有同 Run 资料同步继续原路径；仅存在历史整书记录不阻止本轮按授权收尾。
- 在 `book_task_scope` 的 `subject.update`／`clue.update` 项增加可选 `assetPatch: { revision, quote, replacement }`（不能和代表已满足的 `currentEvidence` 同用）。主 Agent 按需查当前现稿并取得短原文后，登记包含确切变更的原有动作。复用现有 `check_book_scope` 一次核对，把目标和短替换元组一起交给它，仍以当前作者指令、明示限制及同作品同会话引用为准。既有文档级登记和当前修订本身都不能授权任意短句。
- 成功登记后，宿主在本 Run 内保存该目标的精确元组；执行按绑定的作品、会话、当前作者消息、Run、类型、ID 和三元组逐项匹配。不同锚点或不同替换即便有效也不能使用同一登记。精确登记不能走全文 `update`，文档级登记也不能走定点入口；缺少精确范围时仅在有对应授权的情况下走原全文更新，否则保留待办。每项登记只绑定一处；版本冲突后定向重读，经现有登记重新核对未完成项，不自动重放。保留现有目标计数，已提交项的回执不能给不同变更记账。
- 若作者已明确指向某项资料待办但暂不能绑定精确补丁、又无适用的全文更新授权，用原登记记录该目标为 `assetPending: true`（与 `assetPatch`、`currentEvidence` 互斥）。它只计入未完成项，不允许任何写入口；后续有证据时才可在同一登记路径核对并绑定。这样不会因为只登记了可立即写的正文项而误报完成。
- `book_apply_changes` 的普通 scoped 分支仍只接受范围内的大纲与章节目录动作。对主体／伏笔更新给出路由提示：定点用新工具、开放式说明更新用 `book_generate_assets(update)`；不把格式错误归为路由错误，也不把一个不支持的混合批次拆开写。相比在通用工具开局部覆写口或在全文生成工具混入另一套 payload，独立工具便于发现、约束与诊断。全文生成、已读前提及 `check_asset_update_scope` 原样保留，触限窄化也不得把定点登记变成全文候选。

### 3. 只拼接已送达的原文，用共享工作区提交

- 搜索仅定位；用 `book_get_context` 按 ID 分页回读。不使用搜索预览、历史回复、后台读盘或仅元数据来证明已读，也不要求全文可见。用一期的 `sourceReads` 检查当前修订下该唯一锚点的完整范围已实际派发；合并相邻已送达范围，不能跨未送达的空洞。主 Agent 依据现稿区分已发生事实与计划，不按固定措辞或资料类型自动推断事实。
- 复用精确命中和现有单片段长度上限（`patchFragmentLimit`，目前 600 个 UTF-16 代码单元），只拼接一次，不改原文比较的空白或标点。缺失、重复、未改、清空或把整份正文当锚点都不属于该操作。沿用现有文档解析及引用规则，保留原 fields、稳定 ID 和链接；短替换不能删改已有引用或引入结构化关系变更，命中范围外的正文原样保留。
- 只提交一个目标，用 `workspace.writeChanges` 的目标期望修订、取消与通常的版本复核，不另调用资产生成或候选审校。按 `editWriteContext` 捕获实际提交修订，并令 `BookTaskScope.track` 仅把匹配的定点登记关联到该 `workspace.document.committed`；回执给出目标和实际新修订，不回传说明、锚点或替换内容。仅在当前证据或有效回执证实目标已满足时将其计入进度，不假定一次写入满足其它待办或既有同步目标。

### 4. 分开诊断审校、路由和任务结果

- 为正文分支增加 `chapter.patch.review`，用有限枚举区分 `approved`、`denied`、`invalid_verdict`、`incomplete`；正常取得模型回复时记录 `hasVisibleText` 布尔值，不把无法获知的文字状态写成 `false`。用同一补丁 `callId` 和既有审校 `spanId` 对照模型终态；未发起审校的前置拒绝看工具结果和 `chapter.patch.finished`，不伪造审校记录。
- 复用登记、工具候选及终态事件；补充白名单中的资料工具标识及安全的路由／定点结果类别，区分不支持的入口、登记不符、读稿不足、锚点失败、版本冲突、取消和实际提交。按 `runId` 串联登记和写入各自的 `callId`，按提交事件、工具回执及磁盘修订交叉核对；不从 `invalid_options` 或 `run.finished` 单独推断。只记录安全类别、关联标识、计数与允许的修订指纹，不写正文、`assetPatch` 元组或其内容指纹、提示、解释、原始参数或响应。
- 续办以有效目标和真实回执核对：两项已提交或已经核实满足才完成，一项满足且另一项仍待办则为 `partial`，均未满足为 `incomplete`。不重新执行此前仍有效的增补；用受控正常 IPC 路径回归，不用模拟写文件或模型自报代替工具提交。

## Risks / Trade-offs

- 合法的结构化裁决可能与模型自由文字矛盾 → 自由文字不是裁决渠道；保持已有授权与提交约束，测试有文字的明确否决和无效裁决同样零提交。
- 短锚点可能重复、被投影裁掉或因人工保存而失效 → 按实际送达范围和当前修订复核，只定向重读和重新登记；仍不明确时保留待办，有独立授权才走全文更新。
- 受控模型可能总能返回合法裁决 → 夹具覆盖成功、拒绝和部分完成，能验证应用行为但不估算真实供应商误判／触限率。实盘仅可另用隔离快照复验。

## Migration Plan

没有数据迁移；精确绑定仅在当前 Run 有效。先通过独立受控回归，再推进二期委派。回滚移除新增工具和绑定分支、恢复原裁决格式要求；不撤销已提交的作品数据。

## Open Questions

无阻塞决策。历史拒绝的真实裁决内容未留存，本变更不需要恢复它，也不会据此追溯判定实盘是否误判。

## Why

2026-11-24 的人工验收发现，Writer 能理解上一轮的修改方案，却会在作者回复「嗯，就按这个来改」后因工具只检查最新一句而拒绝写入；另一条独立故障是 Messages 工具参数不完整，使未执行任何工具的一轮直接终止整次运行。Harness 输入框还需要点击发送，日常多轮创作缺少用键盘发送和换行的快捷方式。

后续同日复验中，一轮直接指令成功提交新反派、两条伏笔和第 5、6、10 章增补，却在正文落盘后无法更新该轮刚创建的反派说明。工具把它归为既有资料并拒绝更新，完成进度仍报 5/5。角色卡留着「尚未出场」与先前的登场计划，和已保存正文冲突。

## What Changes

- 明确区分「只看方案」与「执行方案」：当作者在同一作品、同一会话中明确同意可核对的上一份方案时，主 Agent 可以执行该方案；直接下达修改指令仍可直接执行，不要求作者重述资产名、ID 或工具用语。
- 支持一项已同意的关联增补在多章分别落盘，例如中期多处埋下反派迹象、后期实际登场。核对现稿、引用、版本和各处插入锚点，保留未涉及的稿件，不把规划、部分写入或会话结束当作完成。
- 关联增补写入正文后，在同一执行范围内同步本次新建的角色和伏笔说明。基于当前已提交正文更新剧情状态与关联计划，核对登场、埋设及回收的各自证据。将必要的资料同步列入完成条件，部分成功时指出尚未对齐的资料。
- 对外层 Messages 响应中已结束但工具参数不能解析的情况，确认该轮尚未执行工具后，仅重取该轮一次。损坏调用不执行、不猜补、不回放已完成的写入；重取仍失败时说明原因与保留的进度。
- 为工具参数拒绝与重取补充可关联的脱敏诊断，能分辨两次尝试和实际工具执行，不保存原始参数、提示词、稿件或凭据。
- **键盘交互变更**：Harness 输入框有焦点时，Enter 发送，原来的换行改用 Shift+Enter；复用现有发送校验和按钮，不误送输入法选字、空白输入或运行中的消息。

## Capabilities

### New Capabilities

无；本次扩展既有能力。

### Modified Capabilities

- `background-agent-harness`：同一会话批准上一方案的承接、外层 Messages 的单轮恢复、Harness 输入框的键盘发送与换行。
- `novel-writing-workflows`：在有效的书内修改范围内生成资产和逐处增补正文／大纲，核对跨章关联、原稿保护、新建资料同步与实际完成状态。
- `local-diagnostic-logging`：记录 Messages 参数异常的有限结构、重取的请求关联，以及修改范围与实际提交的区别。

## Impact

涉及模型协议适配与主循环、会话历史、小说工具与章节插入、诊断白名单、Harness 发送表单、README 及相应的受控与桌面回归测试。问题依据是本地验收记录 `design/20261124/Writer-人工验收已知问题.md`，无需将本机日志或截图提交到仓库。

继续沿用单一主 Agent、版本化 Markdown 作品与现有按钮／IPC；不加入审批弹窗、子 Agent、固定写作阶段、整章替换授权、供应商切换、上下文重写或新的往返上限。不重新打开或改写已归档的 `strengthen-harness-writing-prompts`。

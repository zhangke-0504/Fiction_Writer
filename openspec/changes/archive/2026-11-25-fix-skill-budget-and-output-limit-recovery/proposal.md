## Why

当前预算适配把整书档目标提高到了 65,536，但第一次把 `generate-novel` 送给模型时仍按普通档规划；Messages 主 Agent 的单次输出触限也仍会终止运行。固定放大预算或原样重发，不解决已经达到合适额度却仍一次尝试过多工作的情况。

## What Changes

- 第一条实际携带成功加载的整书 Skill 的合格请求，按现有 `long-writing` 策略和配置能力同时规划输入、输出；保留整书业务状态只在派发后生效的时点。
- 对小说会话的 Messages 主 Agent，在供应商明确报告输出触限且存在可安全缩小的已授权工作时，从最后有效的上下文和真实回执续接一次。后续逐步完成未做事项，不原样重发大批次、不缩小交付目标。
- 触限响应整批不执行；无法安全拆分、缩小后仍触限、没有有效进展或作者取消时停止，保留已落盘成果和可核对的待办；不自动提额、换模型或重开运行。
- 分别记录首次派发预算和有界续接的脱敏证据。不扩展到其他协议或写作子请求的恢复，也不改变坏 JSON 分类、写入授权或 200 逻辑轮上限。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `background-agent-harness`: 让首次携带整书 Skill 的请求正确选档；为明确输出触限建立一次有界的拆小续接，并保持与坏 JSON 恢复的边界。
- `novel-writing-workflows`: 用现有整书目标、确认方案、现稿和回执决定下一小步，并以真实交付区分部分完成与全部完成。
- `local-diagnostic-logging`: 区分预算来源和选档原因，关联触限、续接与停止结果，不保存原始输出或工具参数。

## Impact

- 主循环、活动上下文的请求投影、内置 Skill 派发、Messages 终止分类、小说工具的范围／进度校验、诊断与测试。
- 保留全局模型配置、请求和会话历史的现有预算规则；不增加用户选项、不迁移作品数据、不引入外部运行时依赖。

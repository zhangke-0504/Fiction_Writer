## Why

V1 的「生成全书」需要在 Harness 手动选模式，后台绕过通用 Agent，按固定阶段运行；已有 `generate-novel` 只是该流程的提示词，不能从自然语言发现和使用。人工验收《奥德赛》时，截图中的伏笔因引用校验器未识别的情节点未能写入；另一次运行写到第三章时，Messages 输出未完成。作者需要在同一个输入框发出任务，并能看到可信的保存结果和可续接的失败状态。

## What Changes

- **BREAKING（内部 IPC／交互）**：移除「对话／生成全书」及各单章任务模式和专用续跑入口。保留模型、思考等级、附件、章节上下文和停止；普通提问、整书及单章任务均经同一发送入口和后台 Agent 循环。
- 增加应用内置 Skill 的按需查找与加载。明确的整书指令由模型查找、选用 `generate-novel`，再调用已有小说工具完成，不能改走隐藏的整书流程或以单个工具包装旧阶段机。
- 修复整书伏笔引用：用从工作区读取的稳定 ID 建立关联，对无效引用给出可修正的工具结果，不放宽写入校验。区分正文流未结束和输出达到上限；不提交半章，保留已保存内容，允许同一入口明确续写。
- 验收以《奥德赛》的原始指令为正例：只发送一次，能看到 Skill 调用链，实际保存大纲、主体、有效伏笔和约十章完整正文。聊天、单章请求及两种失败路径单独验证。
- 不引入逐步人工审批、远程 MCP、BM25 索引、通用上下文压缩或长期记忆。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `background-agent-harness`: 统一自然语言发送、后台运行及内置 Skill 发现和加载，移除按任务模式分流。
- `novel-writing-workflows`: 用 Skill 和受校验的作品工具替换固定阶段整书生成；修正引用、正文流失败、实际完成判定及续写。
- `local-diagnostic-logging`: 可核对实际 Skill 检索、加载和工具使用，以及引用拒绝、流终止原因和续写结果，不保留用户内容。

## Impact

涉及 Harness 面板、`session.start` 及 Session 运行状态、后台 Agent 和内置 `skills/`、小说上下文与写入工具、Messages 适配器、诊断和测试。复用现有 Markdown 库、写章预览、版本检查及流式工具往返；不改作品格式、不重放旧工作流，升级不改写既有作品或会话内容。

## Context

V1 的 `session.start` 按 `action` 选择通用循环、直接写章或 `WorkflowStore.run()`。旧整书流程把截断后的大纲作为自由文本交给模型，伏笔阶段生成的 `setupBeatId` / `payoffBeatId` 可能不在校验器实际识别的集合中。截图里的 `clue/hint-troy-embers → beat/beat-departure` 就是这一类拒绝；无法从截图确定原始标记为什么未进入集合。另一次《奥德赛》运行中前两章已保存，第三章报 Messages 输出未完成。两类失败分别处理；没有原始流证据可认定第三章是掉流还是输出触限。

## Goals / Non-Goals

**Goals:**

- 同一小说会话里，作者只用自然语言发出指令。Agent 按需发现整书 Skill，调用已有工具，确实把约定的产物写到当前作品。
- 保留单章生成、追加和显式重写、剧情一致性、现有工作区写入保护、实时预览、停止和中断续写。
- 无效引用可诊断、可有限次修正；不把未完成的流或部分写入称为已完成。

**Non-Goals:**

- 不引入任务审批、强制人工确认、远程 MCP、BM25／向量索引或额外的意图分类服务。
- 不实现通用上下文压缩、模型生成摘要、跨会话记忆或通用任务调度器；无需为这些未来能力添加空接口。作品格式和三个现有协议的公开配置不变。

## Decisions

### 1. 一个发送入口和一条后台运行路径

面板和新版 `session.start` 不再发送 `action` / `restartWorkflow`，只有一个「发送」入口。选中章（仅限会话绑定作品）保留为指代上下文，不是启动某种任务的开关。每轮经现有 `RunManager` 和 `runAgent()`；小说会话能使用作品工具，普通目录继续使用通用文件和命令工具。长任务在切页或关闭面板后继续；同一目录仍只允许一个活跃 Run。

保留 `book_generate_chapter` 的单次写入语义：空章生成、在现有正文后追加、明确要求时重写。重写的授权只依据本轮作者消息及明确的目标章，不从附件、历史、Skill 或模型自行传来的动作值推断；含糊或明确禁止重写时保留旧正文。整书补齐默认只写空白章。保留 `draftChapter()` 的版本前提、流式预览和回读取材。移除旧专用启动、继续和重开计划分支，不保留自动路由到 `WorkflowStore` 的兜底。

### 2. 发现和激活通过普通工具往返

在后台为三份内置 Skill 建立轻量目录，只索引内置 `SKILL.md` 的名称、描述和中文别名。`skill_search(query)` 返回少量匹配候选，不执行、不自动激活；明确的任务由模型选择并调用 `skill_load(name)`，按已注册的 ID 返回所选正文。普通聊天不需要激活写作 Skill；普通目录不暴露小说 Skill。加载内容本身不授予写入权限。

复用现有协议的本地工具调用，不依赖供应商的检索工具；不接任意路径或执行 Skill 携带的代码。保留一致性指导与写章工具内部使用写章 Skill 的能力，不把每一份写作指令都注入每轮。`generate-novel` 指导 Agent 根据当前缺失项做计划、调用工具并处理结果；不新增 `book_generate_novel` 之类一步接管全书的工具。检索排序只是提供候选，不能用关键词、相似度或某个例句代替授权和任务理解。

### 3. 用真实 ID 提交伏笔，失败反馈给 Agent

扩展 `book_get_context`，按需返回紧凑且可分页的章节、主体和已解析的情节点 ID；这些 ID 与写入校验采用同一解析规则，不从大纲截断文本推测。索引不替代修改所需的完整阅读和版本前提。只在本轮记住模型已实际提交的精确版本；磁盘版本不同（包括自动解除关联造成的变化）仍需重读。默认先一起规划大纲和目录，先保存伏笔要依赖的章节与主体，再用已存在的 `setupChapterId` / `payoffChapterId`（以及真实 `subjectIds`）写伏笔。顺序是 Skill 根据依赖和已有稿件选取的做法，不是程序中的阶段枚举。

仍接受既有 Markdown 中合法的情节点引用。新失效引用在写入前拒绝；`book_apply_changes` 把错误类型、受影响文档、关联字段或链接及无效 ID 结构化返回，Agent 通过上下文工具重新查找可用目标，再做有限次纠正。不能确定对应关系时，报告具体缺项；不得为让校验通过而删掉作者要求的关联、虚构目标、放宽校验或盲目重放已提交项。部分提交仍返回实际已提交／未提交项。

### 4. 把流失败作为单章工具结果处理

Messages 有终止事件且 `stop_reason` 为 `max_tokens` 时，报告独立的输出上限结果；未观察到终止事件或正常结束状态缺失时，报告不完整流，不接纳截断正文。异常的流事件或传输错误仍走各自的分类。诊断只用白名单枚举／标志，不保存原始事件。

写章工具在流完整、正文非空、取消及版本检查均通过之后才提交。暂态不完整流仅在该章未写入、仍符合原版本前提且未取消时，允许同一次 Run 对该章重试一次；不会把旧预览当续写前缀。达到输出上限不以原参数自动重放。重试仍失败、触限或前提不成立时，保留已提交的章，清除未提交预览，明确指出目标章和原因。后续章节不应越过失败空章，作者可发新请求调整长度或续写。

### 5. 完成和续接以磁盘为准，不以阶段或模型的声明为准

提供薄的作品完成检查（可作为现有作品上下文工具的检查视图）：整书 Skill 按用户目标登记本次约定的章节 ID；同一目标不能为了报告完成缩减成已写的子集。后台检查约定的大纲、主体、伏笔、目录和正文是否实际存在、引用是否可解析、目标章是已保存作者原稿或已通过写章工具成功提交的正文。只建空目录或拿到模型的完成声明不会记为整书成功。进度按磁盘上的目标章显示（如「正文已保存 2/10」），不保存阶段编号。

复用 Session 历史和 Run 状态，只为未完成的整书任务保存续接所需的最少元数据：原用户消息的引用、已登记的目标章 ID 和最后一次失败点／进度；不保存另一份作品、摘要或附件内容。对于同一 Session 的明确「接着写完」，从原消息取创作方向，由新消息明确变更的指令优先。Agent 重新读取当前 Markdown，保留已完成章及稳定 ID，仅处理缺项；不可满足的变更前提仍报告冲突。该记录只提供上下文和校验目标，不能自行激活 Skill、强制步骤顺序或触发写入。默认不在重新打开应用时自动执行。

### 6. 以工具和落盘证据验收

诊断沿用 Run／轮次／工具关联和内容白名单，区分检索候选、Skill 加载、内容已发给模型、工具实际执行及保存结果。保留写章和回读的子请求诊断，续写记录目标章和跳过已有内容的原因，替代旧阶段／检查点事件。对话与工具记录都不作为磁盘提交证明。

## Risks / Trade-offs

- **模型只复述计划或选错 Skill** → 更新描述和反例，分别用正例、不同措辞、仅讨论及单章请求验证；受控端点验证真实工具走线，另用已配置的真实模型手工验收，不能用合成夹具宣称模型已正确理解意图。
- **十章任务用光模型往返或请求输入空间** → 分批提交、返回紧凑 ID 和状态，十章夹具验证能在明确的有限预算内完成。通用循环保持默认预算；登记整书目标后每个目标章最多增加一次往返。只为明确支持的模型端点扩大必要的输出预留。支持时，整书的纯正文子请求用直接输出而不让长推理抢占正文预算；不改变 Agent 决策轮的思考配置，其他端点维持原行为。不解除上限或借此实现通用压缩。
- **流重试期间有作者编辑或磁盘已部分提交** → 复核版本和真实提交结果，再决定能否重试；不能覆盖已存稿件或重建章节。

## Migration Plan

- 保留原 Markdown、Session 历史、模型配置和既有合法引用。旧工作流检查点不转换、不重放；旧版未完成的作品也可以在新版输入自然语言，按现稿接着写。历史会话仍可读，新版续写元数据不改变作品格式。
- 回退不回滚已落盘内容；旧版本如发现检查点与当前文件不一致，仍遵循原有冲突保护，不能自动执行老计划。

## Open Questions

没有阻塞本次实现的产品决策。真实模型的十章往返预算和流兼容性以手动验收记录为准，合成测试不替代这一步。

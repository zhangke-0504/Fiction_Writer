## Context

`src/Harness.tsx` 默认进入历史页，顶部 `+` 和历史中的「当前小说会话」都立即调用 `session.create`。`src/runtime.ts` 在当前小说的首份快照返回前也提供一个空数组，因此需要区分加载中的历史和已确认的空历史。后台在创建会话时写入历史文件，使用首条已保存的非空作者消息生成标题。

## Goals / Non-Goals

- 作者打开无历史的小说时可以直接输入，并从侧栏顶部找到浏览历史、新建会话和关闭操作。
- 设计范围是小说编辑页的侧栏、会话视图和首轮发送。持久化和启动仍由现有 `session.create` 与 `session.start` 接口完成。

## Decisions

### 用当前小说的快照决定默认视图

让 `useRuntime` 向侧栏提供当前 `bookId` 的快照就绪状态。首次打开时，加载中显示加载状态，读取失败显示现有错误，成功后才根据完整会话列表决定默认视图。有历史时打开历史，无历史时打开「新会话」。切书沿用侧栏按 `bookId` 重置的方式。在同一本书中，关闭后再打开可恢复正在查看的会话。若已经没有会话，下次打开直接进入「新会话」。

用明确的视图状态区分历史、尚未保存的新会话和已保存的会话。作者能主动打开空历史查看提示，之后可用顶部 `+` 返回输入。删除最后一条会话后，历史页可呈现空状态。用搜索结果是否为空来决定视图会让零匹配的搜索跳到输入界面，因此默认视图只读取搜索前的小说会话列表。

### 由首次发送触发持久化

默认打开的新会话和 `+` 共用现有的空对话与输入区，显示「新会话」，创建记录后即可使用已保存会话的删除操作。保持设置引导、模型选择、思考等级、参考文件和章节上下文可用。只有符合现有发送条件的首次提交才调用 `session.create`，随后用返回的 ID 调用 `session.start`。对已保存的会话直接使用其 ID 发送。在请求提交时捕获输入、模型、等级、附件和当前章节，现有的提交保护覆盖创建和启动的全过程。

### 缩短顶部栏并按会话名称匹配

在 `src/main.tsx` 修改入口文字并保留 `Ctrl+Alt+I` 和按下状态。在 `src/Harness.tsx` 让侧栏区域和关闭按钮的无障碍名称使用「AI」，移除重复标题和历史页的创建按钮。顶部三项图标保持靠右，沿用独立滚动布局。在当前 `bookId` 的会话列表上使用原有归一化后的 `session.label` 做子串匹配。

## Risks / Trade-offs

- 创建完成后的会话快照可能晚于 RPC 响应。侧栏在快照接管前继续显示对话，用创建响应中的 ID 发送，避免短暂跳回历史。
- 创建成功后，首次启动仍可能因参考文件不可用等原因被拒绝。保留已取得的会话 ID、输入和附件，显示错误，修正后向同一会话重试。

## Why

一期已限制反复带入主 Agent 的读稿体积，但查证、比较和写入协调仍由同一个上下文串行处理。让主 Agent 把可独立交付的工作交给本 Run 的子任务，可减少主请求反复携带的资料；独立工作能否更快完成、全 Run 成本是否值得，需要以一期为基线验证。

## What Changes

- 主 Agent 可经 `tool_search` 发现 `start_task` 和 `wait_tasks`。任务以简短说明、必要引用和预期产物启动，先返回 ID；主 Agent 可继续独立工作，再按需等待。小说与普通目录共享委派机制，不按措辞、Skill、作品信息或模型触限自动发起委派。
- 子任务在同一 Worker 中独立往返模型与会话可用的只读工具。首版同时至多两个子任务，限制任务总数、请求、读取、报告和耗时；父 Run 结束前取消并等待剩余任务退出。不创建额外会话，不跨 Run 恢复，也不递归委派。
- 主 Agent 只接收有界报告、可回读出处和未查项，可选收取候选文字。等待和报告实际派发分开记录；已有报告不随重复等待反复注入。子报告不是主 Agent 已读原文、范围授权、已完成写入或写入回执。
- 保持现有写作请求、写入前提、原子性及 Messages 逐项续接；不新增 Writer MCP 验证关卡、沙箱或人工审批。用本地夹具验证隔离、并发、取消与证据边界；以一期为对照，单列真实供应商验证。

## Capabilities

### New Capabilities

无。委派是现有 Harness 的通用能力。

### Modified Capabilities

- `background-agent-harness`：增加主 Agent 显式发起的本 Run 只读委派、等待与报告派发；区分主循环和子任务的生命周期、工具目录与回执。
- `novel-writing-workflows`：明确子任务的来源引用与主 Agent 的原文已读证据互不替代，保留现有修订和实际写入前提。
- `local-diagnostic-logging`：关联父 Run、任务、模型请求和报告派发；在不记录内容的前提下诊断等待、资源停止与真实请求重叠。

## Impact

- 涉及 Electron Worker、Harness 循环、工具发现和结果投影、书稿只读工具与诊断契约，以及 Node 和隔离 Electron IPC 回归。复用现有模型协议与配置，不增加运行时依赖。
- 不改 UI、IPC 或公开 MCP 协议，不迁移作品和会话数据，不改主 Agent 和现有生成工具的输出选档。实现完成不代表触限率、耗时或费用必然改善。

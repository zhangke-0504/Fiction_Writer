## Context

一期的[受控对照](../2026-11-26-bound-harness-tool-context/verification.md)已交付有界读取、投影和 Chat 显式触限诊断。十章长稿夹具的主请求输入估算峰值从 51,312 降到 25,937，增补登记前仍是 5 轮，两边实发输出上限都是 8,192。夹具证明体积变化，不证明供应商触限率下降；二期以同一份一期实现为基线。

当前 [`worker.ts`](../../../../electron/worker.ts) 为一次 `runs.start` 组装会话工具、`NovelTools` 和 `BookTaskScope`；[`loop.ts`](../../../../electron/agent/loop.ts) 顺序执行主工具，在实际请求派发时观察工具结果。[`RunManager`](../../../../electron/agent/runs.ts) 负责同一工作区的 Run 独占、停止和退出。现有写章回读是单次选材，不是可供主 Agent 显式启动的多轮子任务。

## Goals / Non-Goals

**Goals:**

- 支持可独立说明、能交付有限报告的通用任务。小说查稿、普通目录核对、审阅和提供候选文字可以共用调度和报告机制。
- 子任务与父 Run 并行推进，仍由主 Agent 理解作者意图、等待依赖、获得写入证据并协调写入。
- 让预算、取消、等待与实际报告派发可以用本地夹具逐项证实。

**Non-Goals:**

- 不并行执行同一主模型回复中的普通工具，不改主 Agent 的选档、生成模板、写入前提和恢复资格，不新增 Writer MCP 验证关卡、工具沙箱或人工审批。
- 不做小说关键词路由、固定角色、任务依赖图、新会话、跨 Run 持久化或递归委派；不额外创建进程、UI 控件、IPC 方法或公开 MCP 接口。
- 不承诺降低全 Run token、费用或输出触限率，不在本期改写 `book_apply_changes` 的全读前提或拆开同章搬移的原子提交。

## Decisions

### 1. 由 Run 持有调度与取消

在 `runs.start` 的操作回调内创建 `RunTaskManager`（拟名）。任务表以 Run 内生成的 UUID 标识任务，持有状态、任务自己的取消控制器、受管理的 Promise 和唯一终态报告。在启动时同步占位，随后异步运行；启动回执不等待子模型，也不表示子任务完成。同一主回复依次启动 A、B 时，正在等待网络的 A 不阻塞启动 B；不能靠把主 `toolExecution` 改为并行或用一个阻塞的批量工具实现父子重叠。

| 操作         | 接口要点                                                                                                                                                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `start_task` | 传 `brief`、`deliverable` 和可选 `references`。继承当前作品或目录、模型配置与 effort；不支持从参数改用其他目录、作品、模型或会话。接受时返回 `taskId`；容量或累计预算不足明确返回原因，不入队。                            |
| `wait_tasks` | 传非空 `taskIds`，可选 `waitMs`。只查询本 Run 的 ID，有尚未派发的新终态就返回；否则等首个新终态或等待截止。返回所请求的已知任务状态、可交付报告及仍运行的 ID；未知 ID 逐项标记，不影响其余任务。没有仍运行的 ID 时不阻塞。 |

父取消、子任务截止和本次等待截止是三个不同信号。等待超时仅解除等待。父循环任意终态都在 `finally` 收口：关闭接收新任务，取消未完成任务，等待全部退出，丢弃任务表之后才让 Run 终结、释放工作区或继续删除。不以 `Promise.race` 提前释放仍在进行的读或流；为子任务使用的 workspace 读取和扫描接入取消，复用现有模型适配器的信号。任务截止只能结束该子任务，不能取消父或兄弟任务。

### 2. 共用执行核心和纯查询，不复制父 RunContext

保留 `runAgent` 的父层适配，将协议往返、工具封装、候选跟踪和请求装配复用于每个子循环。每个循环独立建立工具发现、`ActiveContext` 和原生往返序列；子循环使用小的执行上下文，只有绑定、信号、预算与子诊断，不持有父 `RunContext`、会话历史、附件全文、原生状态、进度、预览、范围或回执写入回调。其首轮只从任务说明、预期产物和明确引用取材。既有写章回读和生成请求继续留在原路径。

主工具通过 [`tool-discovery.ts`](../../../../electron/agent/tool-discovery.ts) 按需发现。委派工具标为控制工具，但不加入现有默认控制 schema；给通用系统提示一条何时检索这对工具的提示，不按业务词路由。子目录在 `tool_search` 前构造，只含当前会话可用的读取能力和任务本地报告能力，不暴露委派、命令执行、父 Skill 激活、整书目标、范围或任何业务写工具；不是在父工具前另加一层拦截。

- 普通目录沿用绑定目录的 `list_files`、`search_text`、`read_file`，引用用相对路径、行或查询位置。路径不扩大绑定范围，不承诺未提供的文件版本信息。
- 书内索引、搜索与分页从 [`NovelTools`](../../../../electron/agent/novel-tools.ts) 拆为共享的只读逻辑。父包装器保留 `novelGoal` 分支及对实际派发的父已读回调；子工具维持同名分页结果以复用一期投影，但没有 `novelGoal` 参数和父状态钩子。明确 `type` 和 `documentId` 的定向读取走 `readDocument`，目录和搜索用既有读取路径；保留游标、字符边界、修订不匹配与不完整覆盖语义。现有 `book_memory_recall` 会刷新落盘索引，本期不注册给子任务。
- 需要对照同版时可向 A、B 传相同的 `{type, id, revision, range?}` 引用集。只读到当前可用修订；修订不匹配明确报告变化，不拼接版本，也不声称 `readAll()` 是跨文件原子快照。子报告的引用用于定位，不自动进入父已读记录。父按既有规则只补读写入需要而尚未读到当前版的出处；过期时重新定位受影响引用，不要求无条件重读整书。

### 3. 给子任务单独的有限预算和终止路径

试点初值是内部常量，不新增用户选项；受控测试可缩短截止和上限。保留同模型的 `standard` 实发输出规划，让对照可用同一上限。独立装配子输入，按现有输入规划及一期单条、同轮、历史的投影规则约束。任务启动参数限制在 4,096 个估算 token 内，其中 `brief` 至多 2,000 字符、`deliverable` 至多 600 字符、引用至多 8 项，不允许用参数内联整本书或完整历史。

| 项目       | 试点默认                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 子任务容量 | 同时 2 个（含尚在退出的任务），本 Run 最多接受 4 个                                                                           |
| 模型请求   | 每任务最多 6 次，子任务合计 16 次；任何允许的同轮额外尝试也占配额                                                             |
| 读取       | 每任务最多 12 次只读工具执行，子任务合计 24 次；新派发的资料及保留历史继续受投影限制，不以文本配额冒充底层扫描字节上限        |
| 任务时限   | 每任务最多 3 分钟；本 Run 的委派窗口从首次接受任务起最多 5 分钟，不限制父 Run 原本的运行时长                                  |
| 等待与报告 | `waitMs` 默认 10 秒、至多 30 秒，0 为查询；每份报告最多 2,048 个估算 token，同轮新增和历史保留的报告各最多 4,096 个估算 token |

在派发模型、执行读工具前预留相应计数，别让两个并行任务同时取得最后一个名额；模型诊断单独记录实际已派发的次数。任一预算耗尽即停止对应任务的进一步工作。主 Agent 的 200 轮上限和现有恢复不变：登记前触限批次零执行，已登记时只有符合资格的 Messages 主 Agent 可进入一次逐项续接；子任务不得触发该路径、提额、换模型或重启整批任务。

### 4. 等到状态不等于报告送达

在子循环注册内部 `task_report`。报告含短结论、少量定位引用、未查项，可选候选文字；保留最近一次完整接受的有界报告，最终报告在完整往返后收口，不另发确认轮。区分 `completed`、`partial`、`failed`、`timed_out`、`cancelled`；遇到预算耗尽或模型失败时，有可交付的阶段报告才返回 `partial`，并保留终止原因。任务时限到时返回 `timed_out`，有完整阶段报告可以附带；父取消不再交付。没有完整报告时返回终态和原因，不从截断回复、进度流或子工具历史补写成果。候选文字不是保存或授权。

等待只读取任务表。父上下文按任务 ID 对同一出站请求去重，保留状态和报告引用，为新报告按整份分配预算；放不下时保留状态并标明可下轮尝试，不能用缺失字段伪装成完整报告。只在 [`loop.ts`](../../../../electron/agent/loop.ts) 的实际出站回调观察派发视图，登记该任务终态和完整报告是否送达；规划、等待或仅派发状态均不能消费报告。配额内可保留近期报告，历史超预算时退为简短引用；首版不提供重发已送达报告的接口，重复等待只返状态，不新增报告副本。按现有规则重发同一请求的合法协议往返不算重新交付，不能因此重跑任务。

主 `start_task`／`wait_tasks` 仅写既有格式的工具回执，零提交，不存任务参数或报告；子工具往返不自动写入父 Session 回执或聊天，主 Agent 的可见答复仍按现有规则保存。诊断用父 `runId`、`taskId`、子任务 lane 和各自 `spanId`；用启动事件关联父工具 `callId`，用交付事件关联承载报告的父请求。记录限额、次数、状态、停止原因和耗时，不落提示、子报告、原文、模型原生状态或工具原始参数和结果。

## Risks / Trade-offs

- **真实并发不等于更省。** 两个子请求以及父工作可能同时占用供应商容量；并发可缩短关键路径，也可增加请求和限流。只限制每 Run 的子任务，不加全局队列或重试。受控夹具以在途请求证明重叠，不用 ID 数或延迟猜；实盘分别看父输入、端到端耗时和全 Run 成本。
- **上下文变小不等于 I/O 变少。** 搜索仍可能遍历书稿，父工具对部分大纲或资料更新仍有全读前提。分别测量读取调用和出站估算；留给另一个变更处理索引或全读瓶颈，不用子报告冒充全文。
- **报告会过期或被预算省略。** 报告要注明出处和未查项，父按实际版本使用证据。不为塞入报告牺牲有效范围、必要 Skill、工具配对和提交回执。父循环收口不自动等待用不到的报告或把未完成任务标成已完成。

## Migration Plan

无数据迁移。先保持父读取和生成行为、提取共享只读逻辑，再接通单任务闭环和同请求派发标记，最后开启双任务并验证 Run 收口。需要回滚时移除父目录注册与 Run 调度接入；旧会话无需清理子状态，已有工具回执不重放。

## Open Questions

- 用一期、单任务、双任务三组同稿对照校准试点预算。使用同一快照、会话起点、供应商、协议、模型、effort 及实发输出上限；真实模型按需求选择工具，不强制并发或指定拆分。主要看主输入峰值、登记前轮数、实际请求重叠、总耗时与提交质量；实际 token 只用供应商给出的可靠 usage，费用缺乏可核对依据时不作比较。
- 验证「黄灯侠」自然增补约束：至少关联两名已有角色、中期线索、后期首次实际出场，以及确有遗留时的同会话收尾。控制样本与可选实盘分开记录；未运行实盘时仅能宣称机制通过。若剩余瓶颈来自大调用或既有全文阅读要求，另评估动作粒度和业务前提。

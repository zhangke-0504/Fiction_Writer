## Context

`.app` 和 `.workspace-frame` 只设了最小高度。章节、主体和伏笔内容随文档增长，最终由根页面滚动。大纲和章节正文共享 CodeMirror 的内部滚动区，目前又通过视口高度减常量和 `350px` 最小高度估算编辑器尺寸。Harness 单独计算高度并使用 sticky 定位。书库从 `library.list` 获取按书名排列的作品，过滤后一次渲染全部结果。

## Goals / Non-Goals

将顶栏、工作区与 Harness 约束在 Electron 内容区内。滚轮、滑块和键盘操作作用于当前区域，书库通过分页浏览。最小受支持的 `760×540` 窗口须保留书库导航、编辑器保存和 Harness 发送等操作。变更范围为渲染层布局、浏览状态和本地测试数据。

## Decisions

### 由应用外壳分配剩余高度

将 `html`、`body` 和 `#root` 约束到视口，应用外壳使用 Grid 或 Flex 排列顶栏与内容区。桌面列、工作区框架及各可伸缩子项沿高度链设置 `min-height: 0`，窄列按需设置 `min-width: 0` 并处理长标题换行或截断。工作区和 Harness 从同一布局获得可用高度，替换现有工作区最小视口高度和 Harness 的 sticky 高度计算。设置页长内容和长弹窗在各自容器内滚动。

### 各区域使用原生滚动

- 侧栏固定故事资产导航以及章节搜索、数量和新建按钮，将章节条目放入独立滚动容器。用紧凑间距和受控的长书名布局为矮窗留出条目空间。
- 主体与伏笔共用中栏的可滚动内容布局。标题和操作区在外，详情的返回按钮也保持可见。伏笔正文和关联主体、埋设章节、回收章节在同一个滚动区。
- 将每个资产列表的滚动位置记录在当前工作区。打开新详情从顶部开始，从详情返回对应列表时恢复列表位置。同一详情收到后台刷新时保留可用的滚动位置。
- 大纲和章节正文使用 `.cm-scroller`。让 CodeMirror 填满标题、编辑状态与保存栏之间的可用高度，去掉固定最小编辑器高度。基本信息表单也使用中栏内的可滚动内容区。
- Harness 延用消息区和会话列表的原生滚动，保留现有消息尾部跟随行为。限制可变高内容占用的空间，尤其是附件列表、长错误提示和可拖高的输入框，在矮窗中为消息区和发送控件留出空间。
- 在各纵向滚动容器使用 `overflow-y: auto` 和 `overscroll-behavior-y: contain`。让可滚动的只读区域可用键盘聚焦并具有可访问名称。Chromium 负责滚轮和原生滑块拖动。

### 书库按可用行数分页

沿用现有作品顺序，先按现有书名和作者匹配规则过滤完整列表，再取当前页。书库分为标题与搜索、可用高度可测的列表区和分页栏。列表使用紧凑且可预测的行高，限制书名、简介及元数据的展示行数，并保留完整书名的可访问名称。用 `ResizeObserver` 观测列表可用高度，由完整行高和边框间距计算每页容量。分页栏的占用空间纳入测量，避免控件显示导致分页容量反复变化。书库保留读取提示入口，长诊断明细在受限弹窗内查看。

分页栏使用「上一页」「第 X / Y 页」「下一页」，边界按钮禁用，空结果保留明确提示。搜索变化回第一页。删除和后台刷新后将页码限制在有效范围内。新建成功后清空搜索，用返回的作品 ID 定位所在页。缩放窗口时以原页面首本作品为锚，重新计算所在页。应用内从作品返回书库时恢复搜索及当前页，所需状态由 `App` 持有。

### 用隔离数据验证实际滚动

沿用仓库的 Playwright Electron 测试入口，以 `FW_E2E` 和 `FW_TEST_ROOT` 启动隐藏窗口。用应用现有接口写入足量章节、主体、伏笔、长正文和分页作品，至少通过正常界面各创建并打开一条主体和伏笔。用本地脚本化模型响应生成 Harness 测试消息。通过 Playwright 鼠标事件验证滚轮和滑块，通过 DOM 读数检查目标、相邻区域及根页面的滚动位置，用界面操作验证控件可达。

## Risks / Trade-offs

- 根页面裁切会使未纳入布局的超高内容难以访问。覆盖长诊断、设置表单、长资产弹窗、编辑冲突提示和 Harness 附件，测试最小窗口下末尾操作。
- 作品行受长度、字体度量和窗口宽度影响。限制行高和换行，按实际列表区域计算容量。覆盖长标题及宽矮窗口，确认每页最后一行和分页控件完整可见。
- 回归测试可直接设置滚动位置来准备边界，但真实操作需用 Playwright 输入验证。至少对工作区列表、长详情和 Harness 覆盖原生滑块拖动。

## Migration Plan

随应用常规构建发布。布局和浏览位置均在渲染层管理，既有书库直接使用新布局。

## Why

已有日志能看见会话压缩和显式记忆工具的执行，却无法区分自动召回没有命中、索引降级，还是命中了但没有随模型请求发出。长篇续写出现断层时，需要在不读取聊天或稿件的情况下定位到具体环节。

## What Changes

- 为 Agent 自动召回、写章自动召回和显式 `book_memory_recall` 记录结果计数、耗时与关联标识；区分成功空结果和失败、取消。
- 记录书内索引首次建立、复用、刷新，以及读取、格式或写入异常后的内存降级；缓存没写成不记为已刷新，也不改变召回结果。
- 在自动召回数据实际交给模型请求传输层时，记录请求关联和有限的来源指纹。能分辨 Agent 请求和实际写章请求，也能将重试分开核对；不把请求已发出当成模型采用了证据。
- 沿用本地后台诊断文件和字段白名单，不记录检索词、召回原文、约定文本或原始路径；补充 README 本地排查方式。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `local-diagnostic-logging`：增加书内记忆召回、索引处理及模型请求携带情况的结构化诊断。

## Impact

涉及作品记忆与侧车写入、Agent 与写章请求的派发钩子、诊断契约、回归测试及 README。不改召回排序、章节边界、工具协议、上下文压缩、侧车或会话文件格式；不增界面提示或远端遥测，也不迁移旧日志。

## Why

一次同会话续办只需把第十章某处段间的 6 个 LF 缩为 2 个，但五次 `book_patch_chapter` 调用均未提交；记录能区分锚点错误、审校前的范围拒绝和一次明确审校否决，不能还原失败参数或认定审校误判。精确的跨段原文已能拼接成功，把不可见分隔符的计数和拼接交给工具，可以让主 Agent 不必在两个自由文本参数里重抄换行和两侧正文。

## What Changes

- 在现有 `book_patch_chapter` 增加单处段间空白动作：用当前修订及相邻普通 Markdown 段落的精确短尾、短首定位，仅把目标处多余的连续 LF 删到剩 2 个 LF（1 个空行）。普通 `quote` / `replacement` 的行为不变。
- 复用本 Run 已有的 `chapter.patch` 范围与 `part`、同修订定向回读、正文语义审校和原子提交。审校仍可明确否决；不省略、不追加审校，不放宽原文匹配与作者授权。
- 成功以实际书稿提交和新修订为准。已是一个空行不写入；无法唯一定位、只收到预览、版本冲突或提交前取消时不改稿。其他段落、章节字段和文档保持不变。

## Capabilities

### New Capabilities

无；这是现有章节定点编辑能力的增量。

### Modified Capabilities

- `novel-writing-workflows`：在已授权的局部正文补丁中支持单处段间空白收尾，保留已读证据、审校与提交语义。

## Impact

改动集中在 `electron/agent/` 的章节补丁工具、定位辅助函数及回归测试。不新增 MCP 工具、范围登记字段、模型审批、依赖或设置；不改 Harness 循环、工具发现机制、上下文投影、模型协议、工作区提交层或桌面 IPC。首版不提供全章格式化、CRLF／混合行尾转换或列表与代码块内的清理。

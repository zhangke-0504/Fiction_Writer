## Context

见 [proposal.md](proposal.md)。原样跨段 `quote` 已能通过 `patchBody`；纯空白 `quote` 不能定位，先缩短 `quote` 再提交也不等于回读原文。这次改的是定点补丁的表达方式，而不是放宽匹配或推翻既有审校。现有 `book_get_context` 已返回版本化原文页，宿主也已记录真正派发给主 Agent 的范围，无需更改读工具或上下文投影。

## Goals / Non-Goals

**Goals:** 作者本轮明确要求，或明确承接同作品、同会话的空白收尾待办时，主 Agent 可用两侧短文定位一处段间空白。由工具从现稿取精确分隔符，交给现有审校并按原有路径提交。成功只缩短所选分隔符，不改两段文字。

**Non-Goals:** 不改 Harness 循环、恢复、协议、工具发现、投影或工作区；不新增 MCP 工具或范围登记、审批步骤，不跳过已有审校。不做整章扫描式清理、不支持任意空行数和通用空白归一化、不改变普通正文补丁、新稿事实勘误、插入回声清理或资料工具。

## Decisions

### 1. 在现有 `edits[]` 中表达单处段间空白动作

`book_patch_chapter` 继续使用 `chapterId`、`revision` 和 `edits`。普通项仍是 `quote` / `replacement`；新项只包含 `paragraphGap: { leftQuote, rightQuote, blankLines: 1 }` 和原有可选 `part`。`leftQuote` 是前段结尾，`rightQuote` 是后段开头；两侧各用一段含非空白字符的单行精确短文，不填中间换行，也不提交替换正文。

首版一次只接收一个 `paragraphGap`，不和普通替换或 `evidence` 混用；若内容修改和空白调整必须原子提交，仍用原有精确补丁批次，不拆开。工具说明提示先按章节 ID 回读当前版。保留 `edits[].part` 的形状以复用同章子目标匹配及现有窄化候选接口，不添加新的范围操作或特殊路由。相较于放松 `quote` 匹配，这个参数只表达一个有明确效果的动作，也不影响已有调用。

### 2. 从同一正文快照派生精确补丁

- 复用现有 `chapter.patch` 范围和 `part` 核对、绑定作品及当前修订。该动作仅供本 Run 已有效登记的正文补丁使用；不能借新稿事实勘误或插入权限执行。
- 复用已安装的 `@lezer/markdown`，只在已定位章节的当前正文中找锚点吻合的两个直接相邻顶层 `Paragraph`。左锚必须是前段的原样后缀，右锚必须是后段的原样前缀。先核对段落对唯一性，再判断分隔符类型和长度；不能利用哪处有更多换行来消除歧义。保留普通精确补丁对展开后 `quote` 的全章唯一性和大小限制。
- 仅替换两段之间 3 个或更多的连续 LF，保留 2 个 LF。不删除同行末尾空格、不穿过中间块，不处理目标处分隔混有 CR、空格或 Tab 的情况。识别解析器可能把 CRLF 的 CR 纳入前段范围的情形，不能把其中的 LF 误认为可单独操作的纯 LF 分隔符。
- 在工具内用同一快照构造 `quote = 左尾 + 原分隔 + 右首` 和 `replacement = 左尾 + 两个 LF + 右首`。复用 `patchBody` 的局部限制与拼接，以及同版正文的 `requirePatchQuote` 检查：两锚和分隔必须都在本 Run 实际派发的主 Agent 原文范围内。搜索预览、旧版或有缺口的页不满足；不把工具内部解析算作已读。

### 3. 沿用同一个审校和提交

把展开后的真实补丁、当前作者指令和已有范围交给 `reviewProsePatch`。只对新动作附带后端计算的原 LF 数和目标 LF 数，便于审校理解实际差异，不把计数当授权。`submit_chapter_patch_review` 仍按原有规则裁决；合法的 `allowed: false` 或不可用裁决仍不提交，不再调用一次审校兜底。采用这一做法而不是跳过审校，是因为当前 `chapter.patch` 登记并不绑定唯一的空白变更，仅证明不改文字不能证明选对地点。

通过后继续用 `workspace.writeChanges` 和现有修订、取消检查；只改目标章正文，沿用 `workspace.document.committed`、补丁结果、`part` 记账及变更通知。优先复用既有错误类别和诊断：定位失败使用 `patch_anchor`；不支持的间隔或无变化使用 `patch_scope`，工具反馈区分已是一个空行与不支持的分隔；缺已读范围用 `context_required`；修订变化用 `conflict`。已是 2 个 LF 时，核对当前同版已读后直接反馈无需改动，不启动审校或返回 `patched`。不自动重试、换位置或重写章节，不将锚点、候选和审校文字写入日志。

## Risks / Trade-offs

- **普通空白不总是段间空白** → 仅受理相邻顶层正文段落的纯 LF 分隔；含空格的空白行、CRLF、嵌套块和有意设计的其他格式不自动改。对空白到底应不应该保留，仍以当前授权及已有审校为准。
- **原文页刚好在段间被裁切** → 按已有反馈定向补读同修订的缺口；不用提示词或预览代替证据。定位不唯一让 Agent 补足两侧锚点，不做模糊匹配。
- **实盘仍可能明确否决** → 这次降低锚点构造难度，不承诺所有供应商采纳动作或批准。受控回归证明符合条件时能落盘，也证明明确否决时零提交。

## Migration Plan

无需迁移。现有调用、稿件和会话记录不变；撤回时只需去掉新增工具参数和工具内分支，不需恢复任何存储格式。

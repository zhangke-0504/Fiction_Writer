## Context

[实盘记录](../../../../design/20261127/harness-local-task-whole-goal-mixup.md)记录了局部任务误登记整书和整书／局部结果混算；这两类边界修复已在本变更实现。2026 年 11 月 27 日的新 Run 暴露了意图选择缺口：本轮作者输入“生成10章内容”，日志中没有 `skill.search`、`generate-novel` 送达或 `novel.goal`；主 Agent 登记并获得核准的只有局部章节动作。这说明流程在整书目标激活前就选择了局部计划；日志不支持还原模型内部的具体判断理由。

本变更前，[`NovelTools`](../../../../electron/agent/novel-tools.ts) 的 `wholeWork` 混用 `wholeSkill` 与整书范围项，这些状态又分别影响工具前提、触限候选、预算和收尾；`assertFinished` 在整书分支跳过局部汇总。此外，局部的精确资料补丁在整书进行中被拒是[现有约束](../2026-11-26-fix-harness-scoped-followup-cleanup/design.md)，不是应当放宽的故障。

## Goals / Non-Goals

**Goals:** 保持现有局部／整书授权边界和混合任务核算；作者要求创作一部 N 章完整故事时，即使不使用“整书”固定词，也选择现有整书注册与激活流程，再开始写入。

**Non-Goals:** 不增加模型调用、工具、审批、校验关卡、关键词路由、交互模式或写入权限；不放宽资料、章序、读稿、版本或同步边界。本次不修改章节 `output_limit`、重试逻辑、预算选档或供应商适配；不改混合进度实现，也不处理段间空白、BM25 或历史 Run。

## Decisions

第 2–4 节记录本变更前一阶段已实现且不重开的预算、混合核算与待办承接决策；本次只重开第 1 节中的意图语义，以及 tasks 1.2、3.1 和 3.5，并新增一次 opt-in 真实供应商验收。不改章节 `output_limit` 流程。

### 1. 将已送达指南、本轮整书登记和活动目标分开

| 事实               | 来源                                                                    | 作用                                                                                                 |
| ------------------ | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 整书指南已送达     | `skill_load` 的完整结果实际交给传输层                                   | 可用于创作指导和合格的预算选档，本身不决定任务范围。                                                 |
| 本轮已登记整书执行 | 当前作品、会话、作者消息和 Run 的有效 `novel.register` / `novel.resume` | 整书写章等既有受目标约束的工具尚无目标时，返回 `novel_goal_required`；提示本轮登记所对应的激活动作。 |
| 活动整书目标       | 已有登记和已送达指南，`novelGoal.register` / `resume` 成功              | 使用完整章序、原有效方向与必需资料，计算整书进度并保存续接状态。                                     |

`ctx.continuation` 只是可供核对的同会话旧记录。从读取候选、完整送达指南、局部工具失败到运行结束，均不凭它自动 `resume`、改写整书目标或继承旧创作方向。已有记录与新整书登记的冲突行为不变。整书激活不取消任何局部登记。

增加短提示的语义说明：作者要求创作一部由 N 章构成的故事、且没有限制在某些已有章节时，视为完整作品交付，即使没有使用“整书”或“完整小说”等词，须以现有 `novel.register` 登记完整目标；“只写第十章”、单章续写、增补场景及局部待办仍走原局部范围。当前目录数量、历史目标和 Skill 不构成意图证据。将该规则补入 `worker.ts` 的主 Agent 指引、`generate-novel` 的描述／Skill 搜索线索及既有 `check_book_scope` 核对说明。既有核对可拒绝用逐章局部候选替代完整交付，但不替 Agent 登记整书，也不拒绝混合请求中明确独立的局部动作。误选时由同一 Agent 使用现有工具重新规划，先激活整书目标再提交整书产物；不扩大宿主拦截范围，也不增加核对调用、模型裁决或关键词路由。

仅改提示词不能消除读 Skill 就切换的宿主行为；只依据活动 `target` 又会让已登记的整书在未激活时退回普通写章。复用本轮登记是两者之间的界线，不引入新的意图分类调用。

本次只重开意图选择和对应回归；不调整 `long-writing`、触限候选、章节生成策略或输出限制恢复。既有预算与结果处理实现保留，不作为本次修复目标。

### 2. 已实现并保持不变的预算与小步行为

- 正常整书路径可先登记范围，再按需加载指南。`loop.ts` 在装配首次携带完整 `generate-novel` 结果的请求前，用有效整书登记判断 `first-whole-skill` 资格。预算夹紧、完整指南保护、调用和结果配对不变。没有登记时实际送达指南仍是一次送达，但请求保持普通选档，不发布整书进度。
- 同一 Run 若先送达指南，后取得有效整书登记，从满足资格后的请求才使用 `long-writing`，不重写早先的派发事实，也不强制重载。已登记却未实际送达指南时，不能用预算选择证明指南已送达或目标已激活。正文子请求只在绑定活动整书目标时用长写作档，继续服从供应商能力。
- `narrowedWritingStep`、`restorePrimaryFailure` 等不再用 Skill 单独判断整书。原有 `BookTaskScope` 局部候选不因误读指南消失；真正的整书只在原有安全条件下沿登记和目标核对推进，不能用小步补造整书意图。混合任务整书已齐而局部未齐时，不把它当成全部完成；没有现有规则允许的小步时保留待办并停止。不增加候选写入口、触限资格或重试次数。

以上为既有实现决策；本次不修改其选档或触限行为。

### 3. 同时核对两类交付，不混用回执或权限

- 用同一次收尾读取的现稿分别运行 `inspectNovelGoal` 与 `BookTaskScope.summarize`、待同步核对。整书登记不是一个已完成的交付项；登记后未激活的整书是待办。整书正常产物不需要重复逐章登记，整书进度不代替显式局部目标（包括同章不同 `part`）。局部仍按实际目标去重，不只按文档 ID 去重。
- 局部只认归属该动作且与现稿修订一致的提交，或按原语义登记的 `currentEvidence`。`assetPending`、零提交的拒绝或其他调用对同一资料的提交都不能替代精确短文的证据。检查 `scope.track` 在混合场景的覆盖：例如 `book_apply_changes` 目前在有目标时不走这一层。对可明确归属已登记动作的真实提交保留归属；整书路径里仅同 ID 的写入不能直接冲抵独立局部目标，应以该目标的有效当前证据核对，不为取回执重复写。
- 活动整书仍不运行 `book_patch_asset`，不切到更大的资料更新权限，也不为提交定点补丁临时卸载目标。若作者确实同时要求两类工作，Agent 可以在进入整书前按既有范围先做可独立的局部工作；仍未完成的在本轮列出，下一轮可走普通局部路径。

复用 `RunInfo.taskOutcome` 和 `WorkProgress`，引入可选的分项数据表示整书章数／资料缺口和局部项数／剩余目标。纯整书或纯局部沿用原展示；混合不相加，`progress.complete` 表示全轮已满足，`novelGoal.check.complete` 只表示整书。中途发布整书进度也不能覆盖已登记的局部待办。

- 只有所有适用目标都满足才报告完成。部分有证据而仍有剩余为 `partial`，均未满足为 `incomplete`；按既有计数和复用语义判断进展，纯局部已满足且无需写入仍可为 `no_write_needed`。
- 整书已完成、局部仍待处理时，正常返回的 Run 可以是 `completed`，但业务结果为 `partial`，不可显示全轮完成。正常收尾按整书核对结果清除已完成的整书续接记录，不把局部待办塞进 `NovelTaskState`；整书仍缺资料或目标时保留既有整书失败原因，不能用局部成功掩盖。取消和中断仍按既有生命周期处理；保留真实提交，不覆盖原失败原因。

### 4. 让下一轮能引用宿主核对过的剩余项

在现有 Run 结果中保留有界的局部摘要（动作、稳定 ID、可选 `part`、剩余计数及必要状态）。需核对作者意图时引用已有会话消息，不复存原文、精确替换元组或写入授权。展示时截取有界条目并标明省略数量，不因省略扣减总数。同书同会话的下一轮可把上一轮的摘要与既有历史、回执一起作为参考数据交给主 Agent 和现有范围核对，使「继续剩下的」不用依赖模型上轮是否自报完成。只有当前作者有效指向且已重新核对的未满足目标进入本轮范围；发生版本变化则读现稿，不重放旧工具参数。不新增后台待办队列或跨会话承接。

复用 `novel.goal`、`writing.task_result`、`model.budget_dispatched` 和提交诊断；混合收尾仍记录局部核对计数。核对以 `runId`、有关工具 `callId`、实际回执和磁盘修订为准，不把 Run 正常结束或指南派发当成写入证据。诊断不记录原文、作者措辞、参数或审校内容。

## Risks / Trade-offs

- 主 Agent 仍可能把简洁多章请求拆成局部草稿 → 明确讲清交付语义并用原有范围核对和 IPC 回归覆盖；本地脚本不能证明真实供应商会自行选对。
- 不能将所有出现章节数的请求都升级为整书 → 仅当作者请求创作整部 N 章作品、未限定章节子集时使用整书目标；“只写第十章”等明确局部要求继续使用局部路径。
- 既有回归主要脚本指定整书范围，不能证明真实模型会从短提示选中整书意图 → 增加精确短提示 IPC 回归，并由显式 opt-in 的供应商验收补充验证；它不取代常规本地测试。
- 同一文档可既是整书产物又是局部目标 → 以对应动作和修订证据核对，而非合并进度数字或按文档 ID 整批记账。活动整书内不能完成的局部定点修订明确保留，不自动改走其他入口。

## Migration Plan

同一变更内交付模式判定和结果核算；旧 `NovelTaskState` 和旧 Run 仍可读，可选分项缺失时保持原展示。不回填或自动清除历史整书目标，不迁移稿件。回滚代码和可选展示字段不撤销实际提交，也不重放任何已处理的工作。

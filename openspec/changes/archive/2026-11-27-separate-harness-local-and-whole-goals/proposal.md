## Why

[实盘记录](../../../../design/20261127/harness-local-task-whole-goal-mixup.md)显示，Harness 需区分局部与整书交付并分别核算。2026 年 11 月 27 日的新 Run 又暴露意图选择缺口：作者只说“生成10章内容”，主 Agent 实际只登记局部章节动作，没有检索整书 Skill 或注册整书目标。

## What Changes

- 整书 Skill 送达、同会话存有旧整书记录、本轮已核对的整书意图，以及活动整书目标分别处理。仅补一章、增补场景或续办局部事项时，沿用现有局部工具和普通预算；不把已有章数或加载指南当成整书授权。
- 对“创作一部 N 章故事”这类完整多章交付，不要求作者使用“整书／完整小说”等固定用词；仍走原范围登记和目标激活。明确只写指定章节或处理局部待办时仍用局部路径，未激活的整书不得改走普通写章。
- 同一轮确有整书和独立局部目标时，分别核对整书产物、局部动作及必要同步。分别显示两类进度；整书完成而局部仍有待办时，本轮为 `partial`，下一轮只处理仍未满足的目标。
- 使用现有主 Agent、Skill 发现和 `check_book_scope` 核对来保留完整请求意图；不新增模型调用、验证关卡、审批、关键词预路由、任务模式或自动执行。不放宽资料路由和提交条件。本次不处理章节 `output_limit`、重试、预算或供应商适配。

## Capabilities

### New Capabilities

无；修正现有能力的边界和结果核算。

### Modified Capabilities

- `novel-writing-workflows`: 按本轮已核对的整书意图及已激活目标区分整书、单章和局部动作；触限后的候选也遵守同一边界。
- `background-agent-harness`: 补充“创作 N 章完整作品”这一意图表达；已实现的预算资格和混合结果核算保持不变。

## Impact

- 涉及主 Agent 多章意图说明、整书 Skill 的发现描述和既有范围核对；预算与混合进度实现保持不变。不新增工具或 IPC 入口，不调整章节 output_limit 或重试，也不与段间空白或 BM25 优化合并。
- 用隔离作品和本地协议夹具走正常 Harness IPC，按 `runId`、`callId`、提交回执及磁盘修订区分实际写入与待办。受控通过不代表实际供应商一定会选对工具；不在例行验收中调用实盘。

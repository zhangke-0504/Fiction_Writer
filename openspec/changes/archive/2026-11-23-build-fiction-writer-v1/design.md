## Context

当前仓库只有 README 和参考资料，没有要兼容的应用或既有规范。图 1–6 作为编辑器和设置参考，图 7–8 作为 Harness 面板参考。小说内容与工作流规则都是本地能力；选择远程模型时，仅模型调用需要联网。工作区约束针对应用管理的稿件，不是给通用 Shell 建权限沙箱。

## Goals / Non-Goals

**Goals:**

- Windows 优先；无模型时，书库、基本信息、小说资产和章节仍可编辑、保存、重开。
- 小说 Markdown 是稿件的唯一事实来源；同一写入和引用规则适用于 UI 与内置小说工具。
- 后台 Harness 不依赖当前页面或小说结构；运行中可导航、回看、停止，且不会盲目覆盖作者输入。
- 单章生成与整书生成共用写章能力；整书每阶段的产物可检查，失败可从未完成处继续。

**Non-Goals:**

- 不做作品数据库、版本历史、导入、归档、自动剧情合并、云同步或多人编辑。
- 不做代理拦截、模型列表发现、用量后台、外部 MCP 服务、沙箱、逐次确认或应用退出后的守护进程。

## Decisions

### 1. 桌面 UI 与后台任务分离

桌面外壳选 Electron，UI 用 React/TypeScript，章节用 CodeMirror 6 的 Markdown 模式；第一版只需要源码式编辑，不引入富文本与 Markdown 双向转换。Electron 主进程管理一个独立 Node 后台进程；由后者持有 `WorkspaceService`、`RunManager`、Session、模型流和工具。通过窄 IPC 接口发命令和转发事件；渲染器不直接执行 Shell 或持有供应商凭据。相比页面内 Agent 循环，这个边界不会随组件卸载而消失；相比常驻 HTTP 服务，不需要再维护端口、客户端身份或退出后生命周期。

书库与设置是顶层页面。工作区默认只有资产导航和正文区；Harness 是应用级右侧面板，应用聚焦时用 `Ctrl+Alt+I` 或可见入口打开。面板的 Session 列表显示绑定的书籍或目录，不随页面切换被重置。章节正文用显式保存（包括 `Ctrl+S`），当前界面运行期间，基本信息和正文的未保存草稿按作品和文档 ID 保留；切页不丢字，收到新指纹时不覆盖草稿。

### 2. Markdown 与稳定引用

作品库采用应用管理的可访问目录（Windows 默认 `Documents/Fiction_Writer/library`）。文件与目录名用生成的稳定 ID，内容采用 UTF-8 Markdown，结构化字段用小型 YAML frontmatter。文件树是事实来源，列表、排序、引用索引是可重建投影，不另存一份稿件索引为事实来源。

| 相对路径 | 元数据 | Markdown 正文 |
|---|---|---|
| `library/<book-id>/book.md` | `id`、`title`、`genre?`、`style?`、`author?` | 简介；新建不写 `author`，已有值只用于匹配，不在 V1 表单里出现 |
| `outline.md` | 无必填字段；可用 `<!-- beat:<id> -->` 标记情节点 | 全书大纲及对主体、伏笔、章节的规范相对链接 |
| `subjects/<id>.md` | `id`、`name`、`kind: character \| item \| scene` | 主体信息 |
| `foreshadowing/<id>.md` | `id`、`title`、`subjectIds`、`setupChapterId?`、`payoffChapterId?`、暂存的 `setupBeatId?` / `payoffBeatId?` | 伏笔内容；同一埋设或回收位置不同时存章节和待绑定的情节点 |
| `chapters/<id>.md` | `id`、`title`、正整数 `order`、`beatIds?` | 本章正文；新建默认空，改名和排序不移动文件 |

关联索引只认类型字段、规范相对 Markdown 链接（如 `[潮汐钥匙](subjects/<id>.md)`）及定义好的情节点标记，不扫描纯文本同名词来猜关系。正常应用写入验证受影响的明确引用；硬删除目标时解除这些引用，保留其他文件、普通文字，以及链接的原显示文字（转成普通文本）。若外部编辑留下不合法 Markdown 或断链，显示 diagnostics，保留原文件供修正，不默默重写，不让一本书的错误堵住整个书库。

### 3. 共享写入、实时预览与重连

- **提交路径。** UI 和应用内工具写入作品均走 `WorkspaceService`；通过文档内容指纹或「应不存在」前提检查进行中途变化。批量编辑先验证受影响的读取集合和待提交后的引用，再在作品级写入队列内执行。单文件先写同目录临时文件，再替换或新增；硬删除文件实际移除。多文件操作不是文件系统事务：全部成功后发布一组变更；部分失败时返回已提交／未提交项，按磁盘实况重读并通知，不自动重放。指纹不是版本库。
- **通知路径。** 落盘事件带 workspace、受影响的文档 ID 和新的指纹，可触发列表与文档重读。外部写入由目录监听及应用重新聚焦时核对触发；已知工作目录内的 Shell 写入在命令返回后也触发重扫。合并重复通知，不以目录监听顺序判定真值。受管理的写入有一致性保证；直接写磁盘的外部进程可以绕过它，监听只能在事后协调。
- **生成路径。** 写章步骤发有明确 `runId / bookId / chapterId` 的增量正文；预览在后台内存中聚合，不作为正文落盘。编辑器仅在目标章且没有未保存缓冲时以只读预览展示并标注「生成中 · 未保存」；续写预览包含原文及正在追加的文本。成功时用生成前指纹提交；停止、失败或指纹冲突不写这份预览。普通 `write_file` 和不完整的函数参数不是预览源，只在确认写入后刷新。
- **冲突路径。** 已有用户缓冲时保留文字并提示背景改动；即使 Agent 在原磁盘版本上成功写入，旧缓冲也不能直接保存覆盖新内容。V1 给用户复制草稿或重载当前文件的选择，不做自动合并。空闲且无未保存内容的编辑器自动刷新；若所选文档已删除，清除选择，仍可复制原本未保存的文字但不会自动重建文件。
- **连接路径。** 后台用全局序号为工作区和 Session 通知排序，运行快照携带游标。重连和序号断档均会重读当前作品投影及运行快照；如果快照游标已越过最后收到的通知，同样刷新作品投影。缓存可有界，不必把每个 token 都写进历史。路由切换不属于取消信号。

### 4. 通用运行器、配置与工具

Session 创建时绑定小说 ID 或用户选定的普通目录的规范路径；新会话默认 `high`，发送时固定模型配置、思考等级、工作目录和本轮附件。切换页面或修改配置不影响已运行的请求。单 Session 一次只跑一轮；同一工作区只允许一个活跃 Agent Run／整书任务，重复启动明确报告忙，不锁住该作品的人工编辑或其他工作区。不同工作区可以独立运行。Session 历史为应用数据目录下的 JSONL 和少量索引元数据，与作品独立。关闭面板或渲染器重载不停止后台；真正退出或后台异常后，未终结的运行恢复为「中断」，不自动重放命令和写入。

先对可嵌入的 Pi SDK 做有退出条件的试验：能否使用自定义供应商、映射流式工具事件、替换内置工具而使用统一写入、独立持有多个 Session 并可靠取消。如果不满足，保留相同事件和工具契约，用薄循环实现「模型流 → 收齐并校验工具参数 → 运行并返回结果 → 下一轮」。失败、超时与模型回合上限均有可见结果。可借鉴 OpenCode 的状态与事件划分，不把整个代码 Agent 产品搬进来。

- **模型配置。** 设置页的名称、Key、Base URL 和单模型 ID 必填；高级区选 Chat Completions、Responses 或 Anthropic Messages。Base URL 保留用户提供的前缀（如 `/gateway/v1`），仅追加对应操作路径；不自行猜网关版本，也不自动试用不同协议和地址。凭据独立保存在应用侧（Windows 用系统保护的凭据存储），按需取用；不放进渲染器读出接口、历史、模型上下文、工具环境或测试输出。接通测试用无稿件的最小请求，区分认证、连接与工具能力问题。V1 实现三种协议的流式工具往返，并用本地 fixture 验证；部署前用指定 DeepSeek 端点单独实测 Chat Completions。
- **协议适配。** 分别处理鉴权、流式工具参数、工具调用 ID 与结果回传、模型/供应商可用的思考等级。对 DeepSeek 等要求工具后续请求保留推理字段的端点，在同一轮的适配器内部保留必要的原生状态；不将私有字段混入跨协议 Session 历史。后续新 Run 换协议时使用规范化的聊天记录，不把上一端点的原生工具状态提交给另一端点。无法映射 `low`、`medium` 或 `high` 时用模型默认值并明确显示。
- **通用工具。** 进程内类型化注册：`list_files`、`search_text`、`read_file`、`write_file`、`edit_file`、`delete_file`、`run_command`。命令从选定目录执行，支持 Windows PowerShell、退出码、限时和取消，验证取消会终止受应用管理的命令进程树。工具结果有输出上限；预期错误以结构化结果送回模型，不挂起 run。显式附加文件在发送时读入本轮，缺失或超限显式提示。普通目录不要求小说元数据。内置工具直接执行，不起 MCP Server，也不为 Shell 做隔离；工具接口可复用到未来 MCP 适配层。
- **生命周期。** 停止共享取消信号，关闭模型流、停止工具并等本轮的文件写入安全点，丢弃未提交预览，保留此前已提交改动。删除活跃 Session 时，在禁用新请求后执行相同停止流程，确认无后续写入再硬删历史并屏蔽旧事件。删除作品时先阻止该作品接受新任务，结束已知绑定到该作品的任务后再删目录；既有 Session 不是作品备份，保留历史但显示工作区不可用。同一 Session 的工作区失效更新与硬删除串行，只有正常新建可以创建历史文件。失败时显示真实结果，不报告删除成功。

### 5. Skills 定义规则，运行器跟踪产物

小说会话在显式启动写作能力时加载对应的内置 Skill。向模型提供 `book_get_context`（按目标读取大纲、主体、伏笔、章节和必要版本信息）、`book_apply_changes`（批量应用带前提的变更）、`book_generate_chapter`（受控正文生成入口）。写章入口请求文本流而非把不完整的 JSON 当正文，写入仍使用共享服务。普通目录的 Agent 不加载这些专用规则。程序检查引用，Skill 判断剧情；手工保存只校验确定性规则，不偷偷调用模型或重写关联系列。

- **故事一致性**：对主体、伏笔、大纲的增删改先读大纲和关联资产，并反向检查受影响的主体／伏笔；按需拿章节上下文。用最小修改对齐有影响的段落或关系，保持未影响内容。悬而未决的语义问题可在结果里说明，不靠名字相同批量删改。明确引用即使不调用模型也可检查。
- **写章与续写**：取基本信息/文风、总纲和目标章定位、前序正文、相关主体及伏笔，以及当前正文（续写必须保留原文）。优先取近期章节全文，预算允许时读全；较长作品用带出处的摘录。前章或目标章有省略时，在正文前用一次只读取材轮给模型提供章节目录，并按 ID、位置或关键词补读最多三段原文；此阶段不生成预览，补读的文件指纹纳入提交检查。新章/空章写入全文，续写只追加；覆盖已有正文需要本轮请求明确要求重写，不从自动流程推断。
- **整书生成**：由后台按「大纲 → 主体 → 伏笔 → 章节目录 → 逐章正文」运行。伏笔阶段可引用大纲情节点；章节目录用 `beatIds` 绑定，在写正文前将暂存关联落实到具体章节或报告不能解析的映射。每个阶段完成前检查文件实际存在、引用和产物有效；逐章复用写章工具和实时预览。已存在的人工作品内容默认复用，不任意覆盖。应用侧记录阶段、计划产物 ID 与提交后指纹（不是稿件备份），避免落盘完成但检查点未确认时重复建文件；失败标明停在哪一步，由用户明确继续。检查点记录创作指令，留空续跑时沿用，输入新指令时替换；参考文件内容不持久化。继续时重核已完成产物，从首个可继续的未完成项开始，已提交成果仍在磁盘；若发生部分写入或人工改动导致前提不成立，报出具体差异，不盲目补写、重复建章或重放命令。

## Risks / Trade-offs

- **切页期间错过事件** → 快照、游标和续接统一由后台提供；首个集成用例用可控假模型注入断点验证。
- **文件被手工/外部写入、Windows 文件占用或监察漏事件** → 指纹前提、只读生成预览、保留未保存缓冲；报告真实部分结果并基于磁盘重建。不承诺多文件 ACID 或对任意外部并发写入的原子比较交换。
- **网关看起来能聊天但工具轮次失败** → 端点能力以实际多轮往返为准，不按协议标签推断；假服务覆盖三个协议的错误和取消，真实 DeepSeek 小样例另验。
- **批量写作可能遗失远处设定，或输出碰巧符合 schema 但不合剧情** → 限定上下文、先检引用再写；以少量有伏笔回收和角色事实的固定样例做人工抽验，不承诺模型能证明语义正确。

## Migration Plan

无遗留小说库或会话需迁移。首次启动初始化空作品库和应用数据目录；回退或卸载运行程序时不删除独立的作品目录。开发第一步应先将 `design/ds_config.txt` 排除在 Git 之外；本地真实 Key 仅由开发者配置的测试入口读取，自动化夹具使用占位凭据。首个里程碑用假模型跑完跨页同步链路，之后再验证真实 DeepSeek、其他协议、完整书库和工作流。

## Open Questions

- Pi SDK 是否通过自定义端点、工具写入接管和取消试验；不通过走薄循环分支，行为不变。
- 指定 DeepSeek 网关和模型对思考等级、流式工具及后续原生状态的实际支持，以小范围往返测试记录，不要求在写提案时读取或调用真实配置。

## Context

`runAgent` 在每轮通过 `ActiveContext` 投影外层上下文并执行本地工具。第一轮实现已让 `book_generate_assets` 与 `book_generate_chapter` 各自构建独立请求，并拒绝空说明交付；`collectChapterReadbacks` 继续提供可选的只读取材。此修订不撤回这些能力，修复的是「资料合格保存」与「当前章可以实际使用」之间的落差。

作者会在同一本书内反复增补、插章和修订。设计保留一个主 Agent 和同一个自然语言入口：创作判断随用户任务而变，资料检查和请求组装按动作封装。已保存的 Markdown 仍是作品依据。

### 2026 年 11 月 24 日现场复盘

- 同一《奥德赛》会话，首次 Run 进入 34 个外层轮次后因 `iteration_limit` 结束，已保存 26 个主体、8 条伏笔、非空大纲和 10 个空白章。随后「继续」的 Run 有 25 个轮次，最后被取消。两次分别有 4 次、3 次 `writing.context.blocked`（`context_required`），**没有一次正文请求派发**。首次还有一次资产请求输出触限，但它不是卡在 0/10 的原因。
- 经本地只读取样，26 个主体均有 `稳定设定` 小节，8 条伏笔均有 `可见线索` 和 `回收真相`；整书目录／资产检查未发现缺项。使用当前构建的 `chapterContext` 直接读取已保存的 `ch01`，无额外 Agent 参数仍复现 6 个主体被报缺项。
- 原因是 `stringsToWithhold` 把未到回收点的句子、引号内短语等放进全章字符串禁表；`visible` 对主体和其他来源整段过滤。诸如「人证」「手艺」这样的普通词，或在别处也出现的旧弓设定，触发一段正常说明整个被丢弃。只在内存去掉未来回收段的引号，6 项降到 1 项；仅在内存替换未来回收段后，原首章 **9 个必需主体、5 条必需伏笔**均可取用。两项对照仅用于定位，并不是上线后删除回收真相的方案。
- `fill` 因已有说明而拒绝，未获当前授权的 `update` 也正确拒绝。笼统的「缺少资料」没让 Agent 区分读视图误判与真实缺档，于是反复读资料、试图换路径；不能用放松覆盖授权、绕过写章工具或延长轮次代替修复。

## Goals / Non-Goals

**Goals:**

- 让主体说明、伏笔说明和章节正文各有可测试的任务模板，共用版本化的书内资料和稳定引用；单独执行、整书逐章和显式续接复用相同能力。
- 在真正派发前核对本次所需的设定、伏笔和衔接条件；区分缺失、已找到但未带入、实际送出。
- 保留作者不按阶段创作的自由：旧书可复用已生成说明；成书后可从一句授权的增补请求出发，将组件关联和实际正文同步小范围落盘。

**Non-Goals:**

- 不增加外层工作流模式、固定阶段调度、子 Agent、独立会话、全书自动状态提取、数据库或向量索引。
- 不自动改写相邻旧章、不全书回填、不改变现有新写／续写／明确整章重写的授权。新增范围只限经授权、可按旧稿锚点验证的**追加式插入**；不实现任意段落替换或删除。
- 不保证识别任意自由文本中的所有矛盾或剧透，只对已定位、已标记和实际选入的资料建立可验证边界。

## Decisions

### 1. 调度与构建分开，分析不隐藏在另一个 Agent 里

```text
主 Agent → 读现稿／按需加载 Skill → 工具调用（目标、动作、简短安排、引用）
       ← 小回执：已保存、缺什么、哪里冲突
                    │
             生成工具校验权限和目标
                    ↓
          读取当前书的版本 → 组装本次请求 → 模型生成 → 验证与提交
                    └── 必要时先做一次有界的只读取材 ──┘
```

- `loop.ts` 仍负责通用轮次、上下文投影和执行工具，不根据关键词切换角色，不持有小说阶段。`generate-novel` 仍通过 `skill_search`／`skill_load` 指导整本目标，`story-consistency` 仍用于关联维护；两者不是写作子请求的模板。
- 主 Agent 负责分析作者意图、作品现状和创作选择，提交简短安排，例如指定本章目标、参与主体 ID、相关伏笔 ID、读者看到什么和需要衔接什么。它主动读到的资料及本轮工具往返占主 Agent 上下文；不要让它把读到的整份稿件再抄一遍。
- 生成工具从当前 `RunContext` 取原始作者要求和已验证的整书续接方向。工具参数中的安排仅是提议，不能成为作者授权。工具用同一模型配置发独立 `ModelRequest`，不继承外层 System、完整聊天、外层工具或模型原生推理。生成稿、拼出的请求及整份取材包不回灌外层；回执只给稳定 ID、修订、结果和可定位的缺失／冲突。
- 取材包的选择、排序、组装和预算裁剪用代码，不调用模型生成 System。已有链接和章节范围不足以定位原文时才补读：沿用已有写章补读的有限一轮选材和最多三段原文；取材只回定位、证据或未找到，不修改作品、不引发其他生成工具，不建子会话。若安排与证据在此处仍不明确，报给主 Agent 决定是再查、补资料还是问作者。

**取舍：** 不把所有模板塞进外层每轮，也不让模型为每次写作另写一套 System。专用请求多占自身的 token 和延迟，但可验证输入和输出边界，长篇资料不随会话历史增长。

### 2. 用同一个构造器，明确三种请求的输入和输出

由 `novel-tools.ts` 的主体／伏笔生成入口和现有 `draft.ts` 调用共享的取材与请求构造器；演进 `chapter-context.ts`，不要再给通用 loop 增加创作逻辑。模板从固定内置映射加载，保留 `write-chapter`；增加主体、伏笔模板。标识、动作块及整书篇幅块由工具和已验证的目标决定，不接收调用方提供的 System 文本或模板路径。

- **System**：共用规则（区别作者约定、现稿事实和计划；资料不是授权）＋所选任务模板＋动作／输出约束。只有已登记或已续接的整书目标获得整书默认篇幅块。正文模板规定场景目标、视角、人物状态承接、伏笔披露、输出语言／格式、新写／续写／重写范围。
- **User 数据**：原始作者要求（显式续接时另带有效的先前约束）、标为提议的本次安排、带来源的相关资料。为主体提供现稿里的身份、动机、关系、限制和有效状态；物品、场景提供其对应的功能和限制。为伏笔提供可见表象、埋设动作、真正含义、回收方式、关联主体及章节。生成的长期设定与随章变化的状态分开表达；后续计划不当作已有事实。
- **输出**：新增一个按 `subject`／`clue` 和 `create`／`fill`／`update` 区分的本地能力（建议名 `book_generate_assets`）。同一小批同一类，返回结构化候选（目标 ID、适用字段、非空 Markdown `body`）；可用已支持协议的受限结果 schema 表达，不暴露实际修改工具给生成模型。代码核对恰好覆盖授权目标、字段和引用正确，确认该批输入版本仍有效，再走既有写入校验，不让外层 Agent 重抄候选正文。章节仍为仅正文的独立流式调用，保持预览、停止、失败及受限重试语义。
- `fill` 只补空白或明确占位；`update` 须在本轮授权内，不能在整书补齐中顺手替换已写的说明。`book_apply_changes` 保留资料字段、关联和有授权的大纲维护，不用通用写入绕过写章。生成候选在落盘前通过与写章相同的可用段落识别和阶段判定：主体至少有可用的稳定设定，伏笔至少有独立可用的埋设表象和真实回收锚点对应的回收内容。先规范化明确无歧义的结构；真正不合格的候选在写入前退回目标和原因，不给出虚假的提交成功。校验的是该资产承担的作用，并不等待全书资料齐备。
- 优先生成短小、同类资产批次，按输出预算给出合理批量建议；遇到触限不照原参数重放。对已落盘的旧格式或旧版生成资料，优先从当前版本得到可验证的局部读视图，不需要机械地为全书每章补一栏，也不因「继续」获得改写非空说明的权限。

**取舍：** 只改 Skill 或让外层 Agent 写候选更便宜，但不足以保证模板实际使用及候选完整落盘；复用现有版本保护和模型适配，不为小批写卡引入新的执行循环。

### 3. 按目标分组取材，先保证必需，随后限制披露

- **必需资料如何定位：** 合并作者或章安排的已解析 ID、目标章／明确对应情节点的已存链接，以及本章有埋设／回收义务的伏笔及其关联主体。显式关联或义务先于关键词记忆；全书大纲里出现名字不让全书卡片变成每章必需。ID 从当前书的可校验索引解析。遇到必须项未绑定、空说明、不可安全投影或关键资料超预算，返回带目标和需补资料的结果，不派发降级正文。附近前文、次要主体和安全的普通摘录按预算取舍。输入估算包含模板、作者原话、必需资料和工具 schema；不能靠整体缩比例把关键块无声删掉。
- **以来源和事实的披露范围取材，不用全局禁词。** 首先按资料类型和已知章锚点选择稳定设定／有前文证据的事实／本章计划／伏笔当前阶段。`可见线索` 和 `回收真相` 单独取用，未到回收不传后者；排期不等于已发生。给资料的有效单元保留来源、修订、原文范围和可用阶段。已标明只在回收时成立或披露的具体命题，即使明确复制到大纲、主体、记忆或补读也不能提前送出；应分离该具体命题，保留同段其他经核验的公开材料。实体名称、引号词、短语、共享设定或与未来剧情相同的局部文字本身不是披露证据，不能据此删除整段或将说明报为缺失。例如早章可使用一把旧弓的公开特征和规则，而不能拿到某人将在比试中借开弓证明身份的结果。
- **兼容既有 Markdown。** 用现有标题、章节链接、明确的事实边界和原文定位选择可用单元；进一步标记确需遮蔽的事实，而不要求重写旧卡。对于无法可靠分离的混合资料，拒用那段不明内容，保留其他已核对片段；仍缺本章所需信息时才返回「说明已存在，但没有已核验的可用摘录」。主 Agent 可另给带出处的安全短摘或改安排；来源不确定不准自动将未来计划转成章节事实。对资料整理仍可读取授权范围内的完整规划。
- **插章和局部续接：** 后接章节已经写好时，另建「必须接到的状态」数据块，来源为作者明确要求或当前旧稿可定位的开场条件，仅传与本次修改有关的衔接事实及引用。它不是章前记忆；不把后章原文或未知真相整段塞给早章。使用当前目录里的稳定 ID 计算邻接关系。若已识别的边界与提议情节明确冲突，附章节和相关资料 ID 退回主 Agent；不得移动埋设／回收、改邻章或默认扩大重写范围。
- **一致快照：** 最终实际使用的关键资料和原文摘录带文档版本、来源范围；提交时同时复核目标、依赖版本和影响本章时序的目录关系。过期时取消提交，让主 Agent 重查；仍复用现有不完整流重试前的校验。预算失败或冲突时不提交正文，也不自动补卡或重写别的文档。

**取舍：** 使用现有 Markdown 与可定位的短证据，不承诺一次扫出所有人物心理、读者知识和剧情真相。正文请求优先隔离已知的后期信息；不能确认时明确报告缺口，而不是拼上全书兜底。

### 4. 按所需产物校验，不设置章节前的全局资产阶段

保留现有整书目标、章 ID／顺序及逐章写空白章。分开判断目录／目标是否有效、下一目标章依赖是否齐全、整书是否完成。整书检查至少要求实有有效大纲、带说明的主体和带说明且埋设／回收绑定有效的伏笔；对于本次明确约定、生成或供目标章使用的主体／伏笔，按具体 ID 核对，而不是用一条完整卡掩盖其他空卡。已有任务继续时按磁盘和会话记录重建已知范围；必要的资料身份随整书记录保留，失败后不能悄悄缩小已承诺范围。与目标无关的旧占位不影响就绪。整书 Skill 引导按现稿补卡，不在后端自动驱动「缺主体就调用伏笔／写章」。

生成候选、写章实际派发和可选的定向只读核对共用同一规则和块来源。要返回能够实际处理的区别：`missing_asset`（无文件）、`empty_description`（确实为空／占位）、`missing_section`（缺所需结构）、`no_visible_evidence`（资料已存在但真实边界无法确定／无可核验可用段落）、`invalid_anchor`、`continuity_conflict`、`budget_limit`；主 Agent 能看到受影响的章、实际资产 ID、所需部分／阶段及建议下一动作。只报直接缺项，不把被阻塞资料的关系依赖连带报成另一个不存在的问题。真空才 `fill`、引用问题查索引、混合旧稿先取有出处的短摘；不提示「已有说明再补空」或「必须给十章逐一写全卡片」。同一修订下不要因同一问题反复读全库或重放章请求。没有新增必须先执行的预检轮次；保留 Agent 重查、修正引用、另选适合的场景或在授权边界内改安排的能力。

在现有 `onDispatch` 记录最终纳入的资料，不记录尚未派发的内容；诊断另区分准备、候选校验、缺说明、内容因真实披露限制被舍弃、引用／衔接失败和输入／输出预算。保留任务、模板指纹、各组计数及脱敏来源，关联 `runId`、`spanId`；不得把未发写章或仅选材算成已派发，不记录原始 System、稿件、工具输入输出或原文摘录。

### 5. 成书后从一句话增加中期反派

主 Agent 根据现稿把「增加……反派及他的伏笔，在故事中期登场」解释为增加资料及一处实际登场戏，不转成新的整书任务。先检查现稿关系和场景，自己选择适合的中期章（十章验收可选第 4–7 章），找两个或更多原有的主体并用稳定 ID 关联；测试使用三个，确保不是同名重复。新主体说明明确关系和剧情用途，伏笔锚定真实埋设章和回收位置，绑定反派及有关旧主体；只改大纲对应情节点／目标章的安排，保存这些引用。既有 Markdown 的主体链接和稿件工具足以表达关系，不引入新工作流或全书剧情数据库。

沿用专用写章请求，增加仅输出**插入片段**的动作（建议在 `book_generate_chapter` 中使用 `insert`）。工具需要稳定章节 ID、当前版本和可唯一定位的段落锚点（可核对的短原文与位置）；向模型提供锚点前后必要的衔接、登场目的、新主体及剧情需要的旧主体说明、伏笔可见内容。仅将结果拼在该锚点，提交前复核作者本轮授权、原文、引用和时序。未改的锚点两侧、其他章节及未涉及的大纲均保留。要求实际登场的明确增补可以授权这个新增动作；仅要求资料、明确不改正文或只是讨论不能授权，原有整章 `replace` 的限制完全不松绑。无法找到无冲突入口时交还主 Agent 尝试其他合法锚点；没有可行位置就报告，不擅自覆盖或将仅写资料冒充已登场。

验收需要看到反派确实在正文登场并且伏笔已呈现可见线索，体现其与既有人物／场景／物品的关系；仅补关系字段或大纲不算。回收若尚未发生，只作为指向既有章的计划，不为补写回收而自动改动另一章或称已回收。章节数仍是十，原顺序与 ID 不变。

### 6. 以真实的连续两条输入验收

1. 空书新会话发「基于神话故事奥德赛来写10章内容」。不再需要第二条指令补齐；正常准备的主体／伏笔一次取用，全部大纲、说明和十章正文真实保存，逐章有派发及提交元数据。不出现由已有有效资料误判造成的重复准备阻塞或轮次耗尽；不把工具调用顺序写成固定脚本。
2. 在同书接着发「增加一个跟2个以上已有主体有关联的反派及他的伏笔，在故事中期登场」。核对新主体（同至少两个不同旧主体的关系）、伏笔、相关大纲和目标章新增段落的实际关联，以及书的其余部分未无故变化。不靠第三条授权重写整章来完成。

受控回归采用普通中文共用词、同义关系、引号和完整命题重复，而非只靠孤立的合成标记。另测首轮失败旧书的只读复验：保留原有回收真相，不重写合格说明，在同一目标下恢复 `ch01` 的就绪。实际供应商验收是独立门槛，记录结果与诊断编号，不用合成端点代替；不承诺模型服务故障也能一次成功。

## Risks / Trade-offs

- [专用生成增加往返] → 主体与伏笔分别小批，复用现稿；常规写一章不启动两个卡片任务或额外分析。
- [空卡检查过严] → 限于 AI 生成和本次确实依赖的资料；明确占位仍可手工保存，不强迫无关卡先补齐。用可测试的空白／占位检查，不以字数替代内容质量。
- [误把共享词或共享前提当成剧透] → 通过逐来源的事实／阶段投影保护真正的回收命题；同一词的合法复用、完整私有命题跨源泄漏分别纳入回归。保留原卡，不以关闭披露限制绕过。
- [插入影响邻章或已有情节] → 按章版本与明确锚点增补，限定原有正文不变；无法衔接则让主 Agent 换合法位置或反馈具体冲突，不扩大授权。
- [排序或修订使已取材失效] → 按目标稳定 ID 重建本次读视图，提交时复核来源和相关顺序；复用冲突、取消和恢复机制。已收尾的整书增补使用新请求，不套回旧冻结目录。

## Migration Plan

不迁移历史 Markdown 或会话。已有稳定设定与伏笔分节由兼容读视图直接消化，旧伏笔也可用安全摘录；升级后「继续」重算就绪并复用已落盘的资料，不能为修复排序或过滤而批量改写旧卡。真正需要补已有空说明时仍以明确授权和现稿为依据。新说明、关联与插入正文都是可编辑 Markdown。

## Open Questions

实施时用现稿形态相近的受控样稿校准批量、词语重复和可用资料边界；不靠固定轮次完成验收。若真实供应商或环境阻塞人工验收，保留该任务未完成并报告实际原因。

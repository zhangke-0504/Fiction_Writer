## Context

Agent 的 Pi 循环负责调度工具，真正发给三种模型协议的是 `runAgent` 单独维护的历史。现有启动逻辑只选最近 12 条文本，不能可靠保存更早的方向；一次长任务内部的工具结果又一直累积。写章使用独立的模型请求，不能只给 Agent 注入记忆。Electron 的 `userData` 和书库目录相互独立，`ProfileStore` 已经按应用存放凭据。复制密文到另一个 Electron 应用数据目录和新建小说不是同一件事。

## Goals / Non-Goals

- 在小说编辑页按稳定的 `bookId` 查看和开启会话，首条作者输入命名；导航不影响后台任务。
- 保留可审计的原始会话和工具回执；压缩模型请求而不是回写聊天记录。
- 同书的新会话和写章都能取回久远情节的原文证据，且前章写作不把后章正文当作已发生事件。
- 不做向量数据库、定时 Dreaming、全局用户画像、新的权限／沙箱／审批或 HITL。仍然只有一个自然语言入口。

## Decisions

1. **分开三种寿命。** Session JSONL 追加作者／助手消息、有限的工具执行回执和 Session 私有压缩检查点。回执只留工具名、调用身份、结果类别及本地提交的文档 ID／版本等结构化证据，不保存参数、原始输出、思考或附件内容。私有压缩没有跨会话共享。作品的 `.fiction-writer/memory.json` 只索引已保存 Markdown 及作者明确要求的长期约定。不要从聊天中自动提炼、传播临时脑暴。继续整书仍依赖已有的进度记录和当前磁盘状态，不从回执重放工具。
2. **从实际请求预算切分。** 估算系统提示、工具 schema、作者输入、会话文本及原生工具协议块，给输出预留空间；按 UTF-8 估算并对含有中文的材料保守计量。跨轮投影以旧消息的计数为检查点，保留首条方向和最近文本；对旧跨度做一次无工具、限时摘要，失败时使用有限摘录。在长任务里先压缩旧的可重读工具内容，仍超预算才把已经完成的完整往返移入摘要，保留最新完整 tool call/result 及其原生字段，不持久化原生状态。保留已加载 Skill 指令以及关键提交与继续线索。若必留内容本身过大，有限地缩减工具内容或明确报错，不发出已知超预算或缺失工具对应项的请求。
3. **以文档版本为准的本地索引。** 使用稳定 ID、版本摘要及带位置的原文切片来索引；未变更的文档复用切片，改变、不可读和删除的文档撤销旧的证据。首次使用、后续召回均按磁盘或写章刚读取的快照验证。写章用作者方向、章名与目标情节点检索，返回版本和原文，读回证据受现有提交 guard 约束。用中文相邻字和英文词的稀有度给相关段落排序，而非仅取最新的头尾。正文事实与计划资料分组，当前写章只采纳此前章节的事实。通过工具可显式查询、记下、更正或遗忘作者约定；当前作者指令优先。侧车的缓存写入失败不回滚 Markdown 或阻止只读取材，不能假称作者约定已成功保存。
4. **UI 和凭据各自绑定到正确范围。** renderer 传 `bookId` 请求限定快照并以该 ID 隔离异步更新，保留全局事件序号协调；普通目录 Session 的后端存储不迁移。离开编辑页卸载面板，返回后可从该书的 Session 继续。`profiles.json` 继续由应用持有，书目录不包含密钥。
5. **Harness 来源。** Pi（`earendil-works/pi@c2f3a5c`，`packages/coding-agent/docs/compaction.md`）提供保留区间＋追加检查点的参考；Hermes Agent（`NousResearch/hermes-agent@8da3100`，`tools/memory_tool_store.py`）参考其限额和原子写；OpenClaw（`openclaw/openclaw@8fa548b`，`docs/concepts/dreaming.md`）参考候选证据与长期事实分开，不引入其后台 Dreaming 流程。实现不依赖这些项目。

## Risks / Trade-offs

- 自定义端点的真实窗口未知 → 使用保守估算、有限输入和明确错误，不当成精确 tokenizer。
- 关键词召回不理解所有同义词 → 结合章信息和证据排序，并保留按关键词补查和定向读原文的能力。
- 作者同时在外部改稿 → 每次从当前版本筛证据；写章提交检查已使用的证据版本。

## Migration Plan

旧 JSONL 可直接读，旧 Session 从第一条有效作者消息派生标题。已有小说的索引按需建立；索引可按现稿重建，作者约定则由作品侧车持久化。旧工作区、Markdown 和供应商配置不搬迁。

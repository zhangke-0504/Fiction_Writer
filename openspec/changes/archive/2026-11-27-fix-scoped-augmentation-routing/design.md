## Context

[提案](proposal.md)针对已完成十章作品上的局部增补。已确认的代码冲突是：`book_patch_asset` 先匹配精确登记，再把本轮新建且有待同步场景的资料指向生成工具；`book_generate_assets(update)` 却在进入同步分支前拒绝该精确登记。现有成功插入、资料创建和同步都有回执，但 `BookTaskScope` 核对候选时看不到本轮创建、关联片段提交及当前版本之间的关系。

新章的两阶段写入已有正常 IPC 路径。本次日志只证明某些登记因目标不存在而失败，不能还原每次调用的参数。已有章的补丁审校确实否决了候选，但没有证据证明裁决有误。修复工具指引和反馈，不根据这些事件放宽写入条件。

## Goals / Non-Goals

**Goals:**

- 对本轮新建且已关联可复核的已提交场景的主体或伏笔，给主 Agent 一条实际可执行、只同步相关状态和计划的路径。
- 保留精确替换、只待办和开放式更新的各自边界；按动作和当前回执分别核对进度。
- 让 Agent 依次建目录、登记正文并写新章；对已有章按新增场景或替换旧文选择工具，不把失败误当作能力缺失。

**Non-Goals:**

- 不改整书意图、资格和结果核算，不改输出触限的触发、步长、预算或重试政策。
- 不新增 Writer 工具、IPC、模型核验调用、审批、沙箱、验证阶段或宿主自动编排；保留既有正文审校、回声、版本及取消语义。
- 不把旧资料、目录字段、大纲、未提交候选或普通正文回执直接当成本次场景同步的授权或事实；不为整章草稿或续写新增场景证明机制。

## Decisions

### 1. 资料同步独立登记，仍用现有工具执行

用 `book_task_scope` 的 `subject.sync`／`clue.sync` 表示本轮受限同步；它们与同一 ID 的 `subject.update`／`clue.update` 独立。让 `BookTaskScope`、两个写资料入口以及下一步提示消费同一套路由判断，返回命中的动作、目标和可用入口，而不是根据文档 ID 或工具名猜权限。

| 已登记动作                        | 可用入口                              | 保留的约束                                                                                                       |
| --------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `subject.sync`／`clue.sync`       | `book_generate_assets(action=update)` | 每个目标只传 ID。仅本轮创建且有可核验关联场景的资料；沿用现有局部状态／计划同步及提交逻辑。                      |
| `*.update` + `assetPatch`         | `book_patch_asset`                    | 仅登记的当前修订、唯一且实际已派发的短原文与替换。一张卡有待同步，不会把合法补丁改送生成工具。                   |
| `*.update` + `assetPending: true` | 无                                    | 记录待办，不授权任何写入；若另有明确且独立登记的同步，只按同步授权执行。                                         |
| 开放式 `*.update`                 | `book_generate_assets(action=update)` | 仅原有开放式授权与当前读稿、候选审校链路。普通更新登记不代替同步登记，不能用来覆盖本轮关联同步目标或绕过其冲突。 |

`book_apply_changes` 仍不支持局部资料更新。因为同一个 `update` 工具也服务开放式更新，按登记和当前目标区分两条分支；入参仍用现有结构。错用路由、没有对应授权或把两类更新混成一批时，不派发该批更新；反馈给出当前实际可执行路径或仍缺的前提，不无条件要求改走另一个工具。同步冲突不回落为全文更新。不能靠调整 `if` 顺序、把精确登记解释为同步授权，或沿用同一个 `*.update` 槽位覆盖独立待办来消除互推。

### 2. 复用场景回执与现有范围核对

从 `NovelTools` 的本轮提交记录及 `story-sync.ts` 已有的片段回溯取得：已创建资料及当前修订、关联章与片段的实际提交、该片段在当前正文可复核的证据。用这些事实判定是否有合格同步目标；把有界、仅涉及候选目标的关联事实送入同一次 `check_book_scope`，与作者指令、可见指代和限制分别标明。模型参数、旧计划、附带资料、未执行候选与旧 Run 的回执本身不能形成写权限。登记结果或 `pendingSync` 提示应区分已可执行、需登记、需核对版本等情况，不把识别到目标误报为获准；不向回执回传正文或在诊断中记录取材内容。

执行沿用现有读稿／片段证据、修订复核和有条件工作区提交，复用当前有效的同步结果。只改已发生状态及被实际剧情取代的计划；保留稳定设定、仍有效的未兑现计划、关系字段、章节锚点和无关段落。伏笔各自按迹象、埋设和实际回收的证据核对，不能因后期有登场就报已回收。

同步和精确更新分别记账；同一同步目标在发现、登记和执行之间不重复计数。一项精确替换可以作为已知的资料修订推进（只有它的起始版本接得上可证的修订链时），但不带 `synced` 证明，不替代资料及关联场景当前版本的有效同步证据；不把外部变更洗成同 Run 提交。任何过时授权和未满足项按现有续办规则核对，`run.finished` 不是业务完成。现有逐项恢复若提供资料下一步，也以相同路由为准，不改变触限恢复政策。

### 3. 把新章依赖和正文动作交还主 Agent

在主 Agent、范围工具和写作指引中说明：作者允许新增章节且安排选中该路径时，先为新 ID 登记 `chapter.catalog`，再用 `book_apply_changes` 的目录创建提交；只有章文档实际存在后，再登记同 ID 的 `chapter.draft`，然后用 `book_generate_chapter(mode=draft)`。目录落盘不是正文落盘。如果未建章就登记 `chapter.draft`，沿用该批不登记和 `missing` 行为，反馈缺哪个 ID、先做什么。对其他缺失及范围裁决失败不误给建章提示。不自动建章，也不强制选择新增章节。

给已有章加新过渡、线索或登场时登记 `chapter.insert`，用 `book_generate_chapter(mode=insert)` 和现稿唯一锚点，只写新增片段。确需修改一句旧文则登记 `chapter.patch` 并走 `book_patch_chapter` 的原审校；补丁被拒不等于允许改用插入，更不能用整章覆盖、放松回声约束或原样重发。真正的续写仍走其既有入口。相较于自动建章或失败后自动换工具，明确反馈让同一 Agent 在作者范围内重新选择，不偷渡动作。

## Risks / Trade-offs

- **同卡有多项动作** → 同步、精确替换与只待办的核对依据分开；用回归覆盖两条入口不互推、精确提交不消掉未满足的同步、以及改版不重放。
- **场景与资料在登记和执行间变化** → 沿用原修订约束；保留真实落盘结果和仍属范围的待办，不改用开放式更新或重复已完成的写入。
- **既有核对的上下文被提交记录挤占** → 只取与本次同步有关的有界事实和必要摘录，不送全书或完整执行历史，不改变模型预算或调用次数。
- **模型不按提示走** → 隔离书稿与脚本夹具只证明宿主路径和可观测反馈。真实模型是否稳定选对工具需另行显式验收。

## Migration Plan

同步登记只存在于本 Run，随工具说明和夹具同时更新；继续使用现有会话待办和提交回执格式。历史 `*.sync` 待办可供本轮核对，但不是可重放的授权。无需迁移作品、会话或 IPC；回退实现不会撤销已保存内容。

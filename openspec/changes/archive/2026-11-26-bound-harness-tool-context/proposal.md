## Why

默认篇幅的小说在整书写完后，局部增补和同会话续办仍曾在范围登记前以实发 8,192 的标准档输出触限、零提交；后续请求的本地输入估算同期从约 5,100 增至 66,397／77,041。这个现象不是已证实的输入溢出，也不能归因于单一原因：一期先减少大页读稿和重复历史给主 Agent 的负担，并让出站体积和真实终态可单独验证。

## What Changes

- 在绑定作品内提供按需、有界的索引、文本搜索和原文分页。返回可核对的文档、修订和位置；默认查询不再把大页原文当作找资料的起点。搜索命中用于定位，原文按需回读。
- 为进入主 Agent 的可重读工具结果设置单条、同轮合计和跨轮历史配额；预算不足时显式分页或退为可回读引用，不改工具调用配对、原生状态、必要的 Skill／目标／待办或真实写入回执。
- 让取材送达与已读范围反映实际出站内容，而不是工具内部执行结果。保留现有版本、精确锚点和任务范围的检查；用长稿对照单独测量资料写入的既有全读前提，不用假读绕过，也不在本期放宽写入规则。
- 增加脱敏的出站体积与投影诊断，区分 Chat 明确报告 `length`、未正常结束、本地取消和超时；不让 Chat 或其他协议获得现有的 Messages 续接资格，不改变模型出站额度或重试次数。
- 保持能力发现、读写顺序和单主 Agent；不新增自然语言预路由、自动召回、校验关卡、审批、工具沙箱、子代理或并发调度。通用委派属于独立二期，不以本期是否完全消除触限为前提。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `background-agent-harness`: 在硬输入上限之前按单条、同轮和历史配额投影视图，同时保留原生协议配对和必要的状态送达。
- `novel-writing-workflows`: 提供绑定作品的限量搜索和可定位原文页，已有读稿、修订与精确原文语义以实际出站为准。
- `local-diagnostic-logging`: 可按请求核对投影、结果送达和明确触限／断流／本地终止，保持日志白名单和不留存内容的边界。

## Impact

- 影响书稿工具和工具发现、主循环出站装配、Chat 适配器、现有诊断契约及 Node／Playwright 回归。书稿工具结果的默认体积变小，继续使用现有会话绑定、工具发现和分页能力。
- 不迁移作品或会话数据，不改写 UI、IPC 接口、公开 MCP 协议、模型配置、整书写作选档或生成子请求，不引入新运行时依赖。用同篇幅的隔离书稿对照一期前后的运行轨迹和实际稿件；不把缩尺或仅成功申请工具等同长稿改善。
